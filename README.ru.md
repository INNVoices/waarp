## Выбор сервера в Windows

После выбора программы открывается единый выбор сервера: **«Автоматически» · «Выбрать сервер» · «Напрямую»**. Сохранённые подключения и публичные серверы представлены компактными строками с поиском и нумерованными страницами. В публичном каталоге также есть фильтры региона и доступности. Сначала проверяются видимые кандидаты, затем ограниченными раундами — остальные, пока открыт публичный раздел. Проверка не добавляет профиль: после свежего ответа строка предлагает «Добавить» или «Использовать». Прогресс различает ожидающих, ответивших, не ответивших и пропущенных кандидатов.

Проверки публичных серверов доступны при включённом Waarp. Смена сервера в карточке применяется без предложения перезапустить VPN; если применить изменение не удалось, прежний выбор сохраняется. Начальный выбор программы остаётся прежним, а схема маршрута и дополнительные настройки доступны в раскрывающемся разделе.

[Описание поведения](docs/SERVER-SELECTION-2026-11-18.md) · [Изменения предварительного выпуска](release/preview-2026-11-18.md)

## Карта и проверка подключения

В Windows `0.4.1-rc.5` карта получила больше места по высоте, сводку по регионам и измеренному состоянию. При сохранении публичного подключения сохраняется распознанная страна. Узлы без известного региона остаются в списке. География встроена в приложение; маркеры стран и линии маршрутов показывают логические связи, а не точные координаты серверов и не traceroute.

Главная вкладка диагностики автоматически начинает ограниченное расследование, объясняет наблюдаемый этап и предлагает следующий шаг. Она учитывает существующий маршрут домена или путь по умолчанию и сохраняет отвечающее текущее подключение. Результат конкретного подключения показан отдельно от системного запроса Windows. Проверка передачи данных и история ответов доступны в раскрываемом разделе.

Android остаётся на r5: прежняя локальная карта, сохранение выбранного региона и контекстная проверка подключения. Её результат остаётся в форме до «Сохранить маршрут». ## Как это работает

Waarp не загоняет весь компьютер в один VPN. У каждой цели своё намерение:

- **Напрямую** — обычная сеть;
- **конкретное подключение** — ваш VPN или прокси, либо их группа;
- **Авто** — выбирает из ваших подходящих подключений и держится за рабочее.

Цели: приложения, сервисы или свои адреса. Режим «весь компьютер» ведёт всё остальное через выбранный путь, а явные правила продолжают работать.

### Авто

Авто предсказуемо и не переоптимизирует маршрут каждые несколько секунд:

- участвуют только ваши непубличные подключения;
- рабочий путь сохраняется, пока через него есть активные соединения; одна пропущенная проверка его не переключает;
- ради скорости путь меняется только при отсутствии активных соединений и после стабильно и заметно лучших результатов проверок; подтверждённый отказ может вызвать переход на резерв;
- проверки ограничены, а движок держит не больше **16** подключений Авто одновременно, поэтому библиотека из сотен профилей не держит сотни туннелей в памяти (остальные остаются в библиотеке, их можно выбрать вручную и проверить в диагностике);
- Авто никогда не уходит в «Напрямую» или на публичный узел. Если подходящего пути нет, маршрут остаётся недоступным, а не утекает.

При переходе на резерв затронутые соединения закрываются, чтобы трафик мог пойти новым путём. Игре или другому приложению может понадобиться переподключение.

### Диагностика

В Windows открытие диагностики или изменение адреса автоматически запускает ограниченную проверку. Waarp показывает наблюдаемый этап — DNS, TCP, TLS или HTTP — с конкретным следующим действием и сравнением допустимых путей. При наличии подходящего доменного маршрута проверка учитывает его; имя приложения не превращается в предполагаемый домен. Подробная системная проверка следует маршрутам операционной системы; при включённом VPN она может проходить через туннель. Проверки конкретных подключений адресуются их native outbound. Причина вроде блокировки провайдером не выводится из одного неудачного запроса. Когда туннель закрыт, отдельная локальная проверка смотрит ограниченный набор ваших подключений без TUN и изменения маршрутов системы.

Показанная задержка — время HTTP-проверки, а не пинг до игрового сервера. Waarp выбирает путь для каждого маршрута; передача одной сессии по нескольким путям одновременно (multipath) не реализована.

### Поддерживаемые подключения

Движок: [sing-box-lx](https://github.com/Leadaxe/sing-box-lx) (в комплекте, с лицензией, в `engine/`).

- AmneziaWG / WireGuard
- VLESS, VMess, Trojan, Shadowsocks
- Hysteria2, TUIC v5
- OpenVPN (скрипты, плагины и внешние файлы ключей отклоняются)
- подписки с поддерживаемыми ссылками подключений, в том числе JSON / YAML с такими ссылками

Импорт из файла, буфера обмена, QR-кода, ссылки подписки, поиска на компьютере или вручную. Подписки обновляются вручную. Из JSON / YAML извлекаются поддерживаемые ссылки подключений; произвольные конфигурации других клиентов не преобразуются.

В Windows `0.4.1-rc.5` публичные кандидаты проверяются автоматически, пока открыт экран каталога. Видимые строки имеют приоритет; остальные проверяются ограниченными раундами с паузами и ожиданием перед повторной попыткой. Уход с публичного экрана снимает его запрос на автоматическую проверку. Ноль доступных серверов описывает текущие измерения, а не отказ всех сохранённых кандидатов. Проверки не добавляют профили и не меняют выбранный маршрут приложения. В Android `0.5.0-rc.5` каталог работает отдельно: для новых проверок публичных узлов пока требуется выключенный VPN. На обеих платформах публичные узлы отделены от «Авто». Их держат третьи лица, не Waarp; операторы могут видеть трафик без сквозного шифрования. Источники: [docs/SOURCES.md](docs/SOURCES.md).

## Осторожное поведение при сбоях Windows

Waarp старается не оставлять после себя изменений в сети и не запускается, если состояние неясно:

- перед каждым запуском он только читает состояние сети: если остался адаптер Waarp или занята его служебная подсеть, он не запускается и ничего не меняет;
- остановка пробует проверенный CTRL_BREAK только при наличии отдельной консоли; иначе завершает свой дочерний процесс через сохранённый handle, затем проверяет выход;
- он никогда не удаляет сетевые адаптеры, не сбрасывает Winsock и DNS и не трогает другой VPN;
- после сна перезапускается не больше одного раза и только когда сеть вернулась.

Покрытие включает офлайн-регрессии, нативные проверки процессов Windows и production-интерфейса. У TUN lifecycle и протокольных тестов отдельные доказательства и границы. Физический сон, выключение, полная маршрутизация, другой VPN и приватный endpoint требуют [закрытия критериев stable](docs/STABLE-AUDIT-2026-11-16.md). Фактические результаты: [журнал проверок](docs/VALIDATION-2026-11-16.md). Контракт отказов: [docs/RELIABILITY.md](docs/RELIABILITY.md).

## Безопасность

- Песочница Electron, изоляция контекста, без Node в интерфейсе.
- Ключи VPN хранятся через Windows DPAPI, без запасного хранения открытым текстом.
- Движок и его DLL сверяются с ожидаемыми хешами перед каждым запуском.
- Импортированные конфиги проверяются до того, как попадут в движок.
- Удалённые и отозванные маршруты остаются заблокированными, а не становятся «Напрямую».
- Небольшой локальный мост позволяет другим приложениям на этом компьютере попросить маршрут для своей цели по токену на один запуск; конфиги и ключи он не отдаёт. См. [docs/BRIDGE.md](docs/BRIDGE.md).

Waarp — инструмент маршрутизации, а не гарантия анонимности: владелец подключения всё равно видит трафик, который через него идёт.

**Защита DNS во время работы; независимого kill switch нет.** Туннель использует временную фильтрацию DNS в Windows (`strict_route`), чтобы ограничить DNS-запросы вне туннеля. Фильтр зависит от работающего движка. Отдельной постоянной блокировки через брандмауэр нет; если движок упадёт, Windows может пустить трафик обычным путём. Не считайте Waarp защитой от утечек.

Об уязвимостях сообщайте по [SECURITY.md](SECURITY.md), а не в публичном issue.

## Сборка из исходников

Для Android есть [инструкция по SDK, сборке, установке и подписи](docs/ANDROID.md#build-and-install). Команды ниже относятся к приложению для Windows.

Windows 10/11, Node.js. Права администратора нужны только при запуске туннеля.

```bash
npm ci
npm run dev
```

Проверки (все офлайн):

```bash
npm run typecheck
npm test
npm run check
npm run build
npm run test:performance
```

`npm run test:ui` самостоятельно запускает локальный сервер production-интерфейса для Playwright. Chromium устанавливается командой `npx playwright install chromium`.

`npm run test:live -- --disposable-windows` создаёт настоящий временный TUN в Windows с правами администратора и проверяет очистку в 50 циклах. Автоматические маршруты и захват DNS отключены. Запускайте только на одноразовой тестовой машине; этот сценарий не доказывает удалённое соединение или полную маршрутизацию. Проверки реального подключения и AWG-библиотеки описаны в [журнале проверок](docs/VALIDATION-2026-11-16.md).

# Waarp: аудит, решения, исследование и ТЗ (ноябрь 2026)

Полная запись обсуждения 17.11.2026: что нашли, что сделали, что решили, что узнали, что делаем дальше.

---

## 1. Что это за продукт

- Открытая оболочка-маршрутизатор трафика для Windows (и Android, ветка GPT). Похожа на ExitLag по концепции и интерфейсу: карточки «приложение / сайт → путь».
- **Своих серверов нет и не будет.** Всё автономно: подключения пользователя, общедоступные хосты, обход без сервера.
- Делаем в первую очередь для себя (ПК + Android). Если покроет большой кусок обходов и фишек — станет популярным сарафаном.
- Цель — блокировки, но это **общий маршрутизатор**: в свободных странах он тоже нужен (игры и пинг, публичный Wi-Fi, гео-доступ, раздельная маршрутизация).
- Не «чисто юзерфрендли»: техническая информация нужна всем, её не прячем (см. п. 7).

### Состояние

- Падений, дампов, отчётов WER нет. Ядро sing-box работало без перезапуска с 23:41, память в норме (sing-box ~100 МБ, Waarp 95–180 МБ).
- Через туннель за сессию ~4.7 / 4.1 ГБ, почти всё — ExitLag.

## 3. Что сделано в коде (не закоммичено, ветка `main`)

### 3.1 Карточки без перезапуска (слоты)

- Каждая карточка получает слот: файлы правил (local rule-set) + свой переключатель туннеля. Ядро само перечитывает файлы.
- Вживую: включение, выключение, создание, удаление, правка, смена туннеля, «Напрямую», перестановка.
- Применение подтверждается «канарейкой»: служебный файл с новым случайным именем + запрос к DNS API ядра. Нет подтверждения за 3 с — один обычный перезапуск (хуже прежнего не станет).
- После правки закрываются соединения только затронутой карточки, приложение переподключается по новому пути.
- До 8 своих туннелей загружаются при старте, чтобы смена туннеля тоже шла без рестарта.
- Рестарт остаётся только для нового незагруженного туннеля, «Русские сайты напрямую», «Локальная сеть», переполнения слотов (12+ новых карточек за сессию).
- Убрана лишняя проверка адаптера при рестарте (~2 с).

**Проверено вживую:** 4 правки подряд — `live route apply ... core and TUN kept`, адаптер не отключался.

### 3.2 Остальное

- **Лог на диск:** `%APPDATA%\Waarp\logs\waarp.log`, 5 × 4 МБ с ротацией. Фазы, ошибки, время старта, применение карточек и причины рестартов, предупреждения ядра. Уровень ядра `warn`, подробный — `WAARP_ENGINE_LOG=info`.
- **DNS карточек приложений** — через их туннель (для программ со своим резолвером: Chrome, Opera, Electron).
- **IPv6:** если у системы нет IPv6, такие соединения «напрямую» сразу отклоняются.
- **ExitLag и другие VPN-клиенты** (WireGuard, Amnezia, OpenVPN, WARP, Hiddify, v2rayN и т.д.) идут напрямую, без двойного туннеля. Своя карточка на них главнее.
- **Карточки Store** совпадают по пакету без версии, дубли сливаются. «Вся папка» у Store-приложения включает и его папку в `AppData\Local\<Издатель>\<Приложение>` (так покрывается `codex.exe`).
- **Интерфейс** показывает карточку по фактическому срабатыванию в ядре.
- **Движок portable** копируется в `%LOCALAPPDATA%\Waarp\engine\<хэш>\` с проверкой контрольных сумм.

### 3.3 Старт с первого раза (собрано в код, вживую не проверено)

- Проблема: первый старт после закрытия старой версии висел ~15 с и падал (`create adapter: ... already exists | open existing adapter: Element not found`), второй проходил.
- Причина: Waarp останавливает ядро жёстко (мягкий сигнал не отправить — у процесса нет консоли), Windows оставляет полуудалённый адаптер. Идентификатор адаптера постоянный: md5(`wintun` + `Waarp`) = `{78F04A7F-86C1-9212-9675-52E8987AC741}`.
- Решение: перед каждым стартом Waarp убирает именно своё полуудалённое устройство `SWD\WINTUN\{78F04A7F-…}` через `pnputil /remove-device` (только если видимого адаптера Waarp нет; чужое не трогается). Если всё равно упёрлось — один тихий повтор без ошибки на экране. Иначе понятный текст вместо «закрой другие VPN».

### 3.4 Проверки

- Офлайн-тесты 35/35, новый тест слотов (49 проверок, включая `sing-box check` конфига и файлов правил), тесты идентификатора адаптера.
- Фризы ПК 17.11 — не от VPN: 4 процесса IDA (`idat -A -Swait.py`) держали по ядру каждый с утра.

## 4. Обстановка по странам (ноябрь 2026)

Источники в основном блоги, форумы, самоизданные отчёты. Вердикты — по совпадению нескольких источников.

### Россия

**Мёртвое:** OpenVPN, WireGuard в чистом виде, IKEv2, L2TP, PPTP, SOCKS5, Shadowsocks/Outline, MTProto-прокси, Tor Snowflake (с 30.03.2026 по отпечатку DTLS), в основном Psiphon и Lantern.

**AmneziaWG:** 1.5 и 2.0 блокируются (признаёт сама Amnezia), рекомендуют 3.1 (август 2026). Независимых тестов 3.1 нет. Часть летних блоков — по IP, а не по протоколу.

**VLESS + REALITY:** живой, но под давлением. Классика «чужой сайт в SNI» ненадёжна → self-steal (свой домен) и XHTTP. Голый TCP режется с февраля. Ноябрь 2025 — сигнатура рукопожатия, февраль 2026 — косвенные признаки, август–сентябрь 2026 — подсети и AS хостеров.

**Как ловят:**

- репутация IP / подсети / AS хостера. Сервер живёт 4–41 день, блок точечный по IP, часть потом разблокируют;
- отпечаток TLS. **Противоречие:** один отчёт — `chrome` (uTLS 133) помечается, брать `firefox`; другой — брать `chrome`. Аргумент за автоподбор;
- залп: >~3 TLS-рукопожатий к одному SNI за ~60 с → молчаливая заморозка ~120 с;
- ~15–20 КБ от сервера с подозрительного IP → соединение глохнет;
- активное зондирование: сервер без настоящего сайта → блок IP;
- поведение: отдача ≈ приём, ровный поток без пауз, нетипичные размеры пакетов;
- несоответствие SNI крупного сервиса и IP хостинга;
- параметры `scMaxEachPostBytes` / `scMinPostsIntervalMs` от 3x-ui 3.0–3.3.0 палятся на мобильных сетях.

**Мобильный интернет:** белые списки (default-deny). ЦФО июль: ~30% сессий без ограничений, приграничье ~90% через белые списки. Пробивается только через разрешённый российский узел с пересылкой (Yandex Cloud надёжнее, VK Cloud почти нет), IP трудно получить. Минцифры давит на хостеров и CDN выносить разрешённые ресурсы в отдельные подсети. UDP режется → Hysteria2 и AWG там не живут. Зарубежный роуминг фильтруется с июля.

**Обход DPI без сервера (zapret и аналоги):** помогает TCP (YouTube по TCP), не помогает UDP/QUIC и блокам по IP/DNS (Discord заблокирован по IP и DNS). Репозиторий Flowseal zapret был заморожен на GitHub 10.07.2026.

**Законы и деньги:** плата за зарубежный трафик (15 ГБ) официально отменена в июле; слух про 50 ГБ на 5G без первоисточника. Бюджет блокировок на 2027 удваивается (~60 млрд ₽ на 3 года). Цель РКН — 92% эффективности блокировки VPN к 2030. ФСБ может приказать отключить мобильную связь. Ограничено 469+ VPN-сервисов (февраль), Discord, Telegram, YouTube замедлен.

**Чего ждать:** движение к иранской модели (шире белые списки, блок по SNI), отключения вокруг выборов и событий, рост блоков по подсетям/AS, смена помечаемых отпечатков, давление на российских хостеров и CDN-ретрансляторы. Выживает то, что неотличимо от браузера, быстро меняет IP и не делает залпов.

### Иран

- Белые списки: по умолчанию всё закрыто, при отключениях пропускаются только DNS, HTTP, HTTPS.
- Платный «Internet Pro» для избранных профессий.
- Блэкаут январь–май 2026, ещё один в сентябре. При полном отключении не помогает ничего. Текущий статус точно не подтверждён.
- Популярный приём там — подбор «чистых» IP Cloudflare для конфигов за CDN.

### Китай

REALITY считается лучшим; Hysteria2 без обфускации, по сообщениям, определяется на China Telecom с февраля; WireGuard получает RST, Shadowsocks — эвристика энтропии. Данные из коммерческих блогов.

### Остальные

- **Туркменистан:** белый список, государственные «разрешённые VPN», лучше всего REALITY.
- **Пакистан:** лицензирование, с декабря 2025 блок Proton, Mullvad, WARP, Psiphon.
- **Мьянма:** ~1500 разрешённых сайтов, фальшивые VPN-ловушки.
- **Беларусь:** запрет и сетевая фильтрация. **Турция:** DPI. **Казахстан, Узбекистан:** точечные блоки.
- **Афганистан:** блэкаут 2025, по вендорским данным VPN криминализован (не подтверждено).

## 5. Протоколы

### Решения

- Свои протоколы **не делаем**: без своего сервера бесполезны, блокируют по форме трафика и репутации IP, новый протокол получит сигнатуру как только станет популярным.
- Делаем **гибкость всех популярных протоколов** и подстройку на клиенте: подмена браузера (отпечаток), TLS, SNI, MTU, паддинг, дробление, мусорные пакеты AWG.
- «Хитрость эпохи ИИ» — не новый протокол, а **машинный перебор параметров маскировки** под конкретную сеть с запоминанием.

### Таблица

| Протокол | Вердикт | Движок sing-box-lx | Waarp сейчас |
|---|---|---|---|
| VLESS + REALITY + XHTTP (+ Vision, + VLESS Encryption ML-KEM) | Основной | Есть всё | Импорт есть: xhttp, режимы, `encryption`, `pqv`, `xPaddingBytes`, xmux |
| VLESS + REALITY + TCP / Vision | Только домашний интернет | Есть | Есть |
| AmneziaWG 3.1 | Берём, не основной | AWG 3.x есть | Есть 1/2 (S3/S4, I1–I5), **нет параметров 3.1** |
| Hysteria2 (Salamander + прыжки портов) | Запасной, при белых списках не живёт | Есть | Salamander есть, **прыжков портов нет** |
| NaiveProxy | Берём: отпечаток как у Chrome | Есть | **Нет** |
| MASQUE / WARP | Берём: бесплатный путь без сервера | Есть | **Нет** |
| TrustTunnel | Берём на пробу | Есть | **Нет** |
| AnyTLS | Берём на пробу (паддинг против «TLS в TLS») | В основном sing-box | **Нет** |
| TUIC v5 | Оставить | Есть | Есть |
| Trojan, VMess | Для старых подписок | Есть | Есть |
| Shadowsocks | Свободные страны, старые конфиги | Есть | Есть |
| OpenVPN | Совместимость, свободные страны | Есть | Есть |
| ShadowTLS v3 | Не брать (два публичных детекта) | Есть | — |
| Mieru, Juicity | Пока нет (нет в движке, нет данных) | Нет | — |
| Tor WebTunnel | Позже, аварийный медленный путь | Нет | — |

### Нюансы

- `finalmask` (маски заголовков, шумы, Sudoku, XICMP, XDNS) и полный набор «хитрых» параметров XHTTP — только в Xray. Xray вторым движком не берём, следим за портированием в форки sing-box (sing-box-extended, sing-box-lx уже портируют XHTTP).
- Xray ≥ v26.9.8 отказывает клиентам без `X25519MLKEM768` в REALITY. Форк умеет — **проверить, что Waarp включает по умолчанию**, иначе новые серверы не подключатся.
- Цепочки (`chain`) в движке уже есть.
- Xray ≥ v26.10.21 рекомендуют, v26.7.11 избегать; с v26.7.11 Xray не шлёт голый VLESS на публичные адреса.

### Что меняется на клиенте (кандидаты для «Подобрать»)

| Группа | Параметры | Сервер |
|---|---|---|
| TLS-протоколы | отпечаток (firefox / chrome / safari / random), ALPN, версия TLS, дробление ClientHello и TLS-записей | Не нужен |
| REALITY | выбор из разрешённых `serverNames` / `shortId` | Если разрешено несколько |
| XHTTP | режим (`packet-up` / `stream-up` / `stream-one` / `auto`), `xPaddingBytes` диапазоном (100–1000), xmux явно (~2 соединения) | Частично |
| Hysteria2 | прыжки портов, полоса | Диапазон на сервере |
| AmneziaWG | Jc / Jmin / Jmax, I1–I5 (имитационные пакеты), MTU, keepalive | Не нужен; S1/S2/H1–H4 должны совпадать |
| Конфиги за CDN | «чистые» IP Cloudflare | Не нужен |
| Сеть | MTU TUN, DoH / DoT / DoQ, резолвер для адреса сервера | Не нужен |

Поведение клиента против детекта: ≤3 рукопожатий к SNI за 60 с, без залпа при старте, паддинг/время жизни соединений диапазонами, при заморозке ждать ~130 с и не менять отпечаток.

## 6. Идеи и решения по ним

| # | Идея | Решение |
|---|---|---|
| 1 | Обход DPI без сервера | **Берём** — путь карточки «Напрямую + обход DPI» |
| 2 | Умные списки блокировок | **Берём, без хардкода** (п. 6.2) |
| 3 | Диагностика | **Берём, её не хватает** — нынешнее «Проверить ссылку» почти бесполезно |
| 4 | Цепочки серверов | Позже (для мобильных белых списков, нужен российский узел) |
| 5 | Протоколы | **Берём** гибкость всех популярных, без своих (п. 5) |
| 6 | Сообщество и публичные хосты | **Берём** (п. 6.3) |
| 7 | Перенос ПК ↔ Android | Рано |
| 8 | Языки (англ., фарси) | Рано |
| — | Свои серверы, mesh, P2P-раздача, полный kill switch (WFP), телеметрия | Не делаем |

### 6.1 Общий пробник

Диагностика, обход DPI и «Подобрать» — одна функция: проверка цели или сервера разными способами + запоминание, что сработало в этой сети (память по сетям уже есть). Проверочный sing-box без TUN уже есть.

### 6.2 Списки без хардкода

- Список — данные, а не код. Реестр «источников списков»: адрес, формат, частота обновления, контрольная сумма. Стандартные источники — строки в реестре, их можно выключить, заменить, добавить свои.
- Форматы: rule-set sing-box, простые списки доменов, geosite, антифильтр. Удалённые rule-set ядро обновляет само, со слотами — без рестарта.
- Курирование: отдельный git-репозиторий `waarp-lists`, PR от сообщества, CI проверяет дубли, мусор, опасные шаблоны (`com`).
- Локальное обучение без телеметрии: напрямую не открылось, через туннель открылось → запомнить для сети → «добавить в карточку?»
- Заменить зашитые 15 доменов «Русские сайты напрямую» и пресеты сервисов на обновляемые списки.

### 6.3 Общедоступные хосты и сообщество

- «Доверия» нет: есть общедоступные хосты (из git-списков, из интернета, списки обновляются) и хосты, которыми делятся люди (например, свой AmneziaWG).
- **Подтверждение владельца** (доказывает ответственного, не честность): TXT-запись `waarp-verify=<ключ>` на домене хоста; подписанный коммит в репозитории списка; для хостов только с IP — подписанный файл, отдаваемый через сам туннель.
- **Проверка честности клиентом** (локально, через туннель): нет подмены сертификатов (сверка с эталоном; в Android-ветке уже есть `CompromisedCaGuard`), нет вставки контента (хэш известного файла), нет подмены DNS, страна выхода совпадает, нет редиректов и рекламы. Провал → красная метка, запрет.
- **Рейтинг без наших серверов:** репозиторий со списками сам гоняет проверки через GitHub Actions (честность, аптайм, пинг) и публикует результаты файлом. Ограничение: машины GitHub в США/Европе, проходимость блокировок меряет только клиент локально. По желанию пользователь отправляет замер через issue/PR.
- Публичные хосты **никогда** для кошельков, почты и других «чувствительных» карточек (бывают ловушки, как в Мьянме).
- Делиться своим хостом с отдельным ключом и лимитами — это управление сервером, позже.

### 6.4 Самозащита приложения (служебный канал)

Задача: приложение не должно ломаться, если недоступно то, откуда оно берёт данные (GitHub, списки, обновления).

- **Опись зависимостей:** источники каталога (VPNGate, git), rule-set, обновления (GitHub Releases), адреса проверок (`gstatic.com/generate_204`, `cp.cloudflare.com`), DoH `1.1.1.1`. Для каждой — поведение при недоступности.
- **Сначала локально:** сборка несёт снимок данных, скачанное кэшируется с подписью, запуск никогда не ждёт сети, обновление в фоне, возраст данных виден.
- **Подпись вместо доверия к источнику:** всё скачиваемое подписано Ed25519 (minisign), ключ зашит. Подписанное можно тянуть через что угодно, включая публичные хосты — подделать не смогут. Защита от отката: версия + срок годности. Смена ключа: новый подписан старым, мастер-ключ офлайн.
- **Зеркала:** GitHub raw, jsDelivr, GitHub Pages, Codeberg/GitLab, Cloudflare Pages, при желании IPFS. Список зеркал подписан и обновляется. DNS TXT-«маяк» с хэшем данных и адресами зеркал.
- **Лестница путей для служебного трафика** (через движок, отдельный локальный вход с паролем и свой переключатель): напрямую → с обходом DPI → через туннели пользователя → через публичные хосты → через CDN. Удачный путь запоминается для сети. При закрытом туннеле — проверочный sing-box без TUN.
- **Аварийный набор офлайн:** файл/QR со списками, зеркалами и (по желанию, под паролем) своими подключениями — через Telegram, флешку; импорт без интернета.
- **Обновления** тем же механизмом: подписанный манифест с хэшами, любое зеркало, неподписанное не запускается.
- **Видимость:** строка «Служебная связь» — когда обновлено, через какое зеркало и путь, «работаю на кэше от …».
- Не делать: зашитые свои прокси, телеметрию.

## 7. Видимость и режим разработчика

- **Обычный режим:** в карточке подключения бейдж протокола (VLESS·REALITY, AWG2, Hy2), страна, пинг, состояние. «Подробно»: адрес, порт, транспорт, SNI, отпечаток TLS, MTU, сработавшее правило.
- **Режим разработчика** (в настройках, добавляет элементы в интерфейс): сырой конфиг подключения и итоговый JSON ядра, живые параметры маскировки, цепочка и правило каждого соединения, лог ядра в реальном времени, версия движка, «экспорт для отладки», «скопировать как ссылку».

## 9. ТЗ: этапы

### Главная цель

**Waarp сам держит нужное рабочим:** пользователь говорит, что ему нужно; если перестало открываться — Waarp понимает почему, говорит это понятно и одной кнопкой (или сам) переводит на путь, который работает в этой сети. Без своих серверов.

### Э0. Закрыть текущее

- Влить в `main` всё из п. 3.
- Живая проверка: старт с первого раза после закрытия старой версии (в логе строка об уборке адаптера), 10 правок карточек подряд без `[apply] ... restarting`.

### Э1. Диагностика «почему не открывается»

Вместо «Проверить ссылку». Проверка по путям: напрямую, напрямую с обходом DPI, через рабочие пути пользователя.

| Признак | Вердикт | Кнопка |
|---|---|---|
| Системный DNS ≠ DNS через туннель / DoH | Подмена DNS | Зашифрованный DNS |
| TCP к IP напрямую не устанавливается | Блок по IP | Туннель |
| С настоящим SNI падает, с другим SNI на тот же IP проходит | Блок по SNI | Обход DPI |
| Проходит только с дроблением ClientHello | DPI | Обход DPI |
| TCP проходит, QUIC нет | Блок QUIC | Запретить QUIC для карточки |
| HTTP 451 / редирект на заглушку | Заглушка провайдера | Туннель |
| Не проходит ни один путь | Белый список / отключение | Честно: поможет только разрешённый узел |

- Пассивная часть: по живым соединениям серия сбросов/таймаутов к домену → «похоже, режется — проверить?»
- **Готово, когда:** на YouTube, Discord и заблокированном сайте вердикт совпадает с реальной причиной, кнопка создаёт рабочую карточку без ручной настройки.

### Э2. Путь «Напрямую + обход DPI»

- Четвёртый вариант пути карточки. Дробление ClientHello и TLS-записей, для карточки QUIC отклоняется. Применяется вживую через слоты.
- **Готово, когда:** YouTube открывается без туннеля на домашнем интернете в РФ, переключение карточки не рвёт другие.

### Э3. Подключение держится само

- Поведение клиента против детекта (п. 5, последний абзац).
- В группах и Авто быстрый уход с заблокированного IP, статус «IP заблокирован».
- Кнопка «Подобрать»: перебор клиентских параметров (таблица п. 5) через проверочный движок, результат запоминается для сети и применяется сам.
- **Готово, когда:** подключение, не проходящее с настройками из ссылки, после «Подобрать» проходит или получает честный вердикт «блок по IP»; при следующем входе в эту сеть применяется само.

### Э4. Импорт под живые протоколы

- Добавить: NaiveProxy, MASQUE/WARP, AnyTLS, TrustTunnel, прыжки портов Hysteria2, параметры AWG 3.1.
- ML-KEM в REALITY по умолчанию.
- Вычищать из XHTTP `scMaxEachPostBytes`, `scMinPostsIntervalMs` с пометкой «не применено».
- Не добавлять ShadowTLS, Mieru, Juicity.
- **Готово, когда:** ссылки каждого типа импортируются, проходят `sing-box check` и подключаются.

### Э5. Видимость

- Всё из п. 7.
- **Готово, когда:** всё, что Waarp знает о пути, видно без чтения файлов.

### Э6. Списки (п. 6.2)

Реестр источников, rule-set с автообновлением, `waarp-lists`, локальное обучение, замена зашитых списков.

### Э7. Самозащита приложения (п. 6.4)

Порядок: опись + снимок в сборке + подписанный кэш → подписанные зеркала → лестница путей → аварийный набор → обновления.

### Э8. Общедоступные хосты (п. 6.3)

Подтверждение владельца, проверка честности клиентом, рейтинг через GitHub Actions, запрет для чувствительных карточек.

### Порядок

Э0 → Э1 → Э2 → Э3 → (Э4, Э5 параллельно) → Э6 → Э7 → Э8.

### Позже / не делаем

- Позже: цепочки серверов, ПК ↔ Android и общий компилятор правил, языки, раздача своего хоста с отдельным ключом, Tor WebTunnel, второй движок обхода DPI уровня zapret (WinDivert).
- Не делаем: свои серверы и протоколы, Xray вторым движком, mesh, P2P-раздачу, полный kill switch, телеметрию.

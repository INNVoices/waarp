# Аудит и исправления Waarp — 16 ноября 2026

## Результат и границы проверки

Аудит выполнен по исходникам относительно `7d1dda574daae2ded00c3d152f71aaa12ece896b`. Изменения устраняют подтверждённые ошибки интерфейса, отмены подключения, применения маршрутов, проверки каталога и импорта протоколов. Модель продукта сохранена: **цель → Напрямую / Авто / выбранное подключение**, один владелец TUN и один главный переключатель.

Это проверенный на уровне исходников, сборки и офлайн-сценариев набор изменений. Он **не является подтверждением готовности Windows-релиза**. Настоящий Wintun, смена физических сетей, UDP игровых серверов, сон Windows и аварийное завершение ядра в этой среде не запускались. Скриншоты изменённого интерфейса и исполнение DOM-сценариев также не получены: запуск Chromium был отклонён средой.

## Продуктовые решения

| Оставлено | Упрощено или уточнено |
| --- | --- |
| Правила для приложений, сервисов и своих адресов; отдельный режим всего компьютера | Настройка маршрута не включает главный переключатель сама |
| Свои WireGuard/AmneziaWG, VLESS, VMess, Trojan, Shadowsocks, Hysteria2, TUIC, OpenVPN | Импорт отвергает неподдерживаемую семантику вместо молчаливой подмены транспорта или проверки сертификата |
| Авто и пользовательские группы | Здоровые активные сессии удерживаются; улучшение скорости переключает путь при простое |
| Публичный каталог | Открывается из раздела подключений; обновляется явно; не выбирается молча для всего компьютера |
| Диагностика DNS/TCP/TLS/HTTP | Задержка HTTP-проверки не называется доказательством игрового ускорения или работоспособности UDP |
| Подписки | Ручное обновление с сохранением старого списка при ошибке; неоднозначные записи не присваиваются прежним маршрутам |
| Один сетевой движок | Не добавлены второй системный прокси, новый сервис, аккаунты, маркетплейс, фиктивный рейтинг ускорения или собственный протокол без сервера |

Из интерфейса убраны неработавший переключатель DNS и плитки с обещаниями будущих возможностей. Нужные сведения о DNS перенесены в пояснение реального поведения. JSON/YAML описаны как контейнеры с поддерживаемыми ссылками: это не универсальный импорт нативных конфигураций Clash или sing-box.

## Исправленные проблемы

### Подключение, отключение и восстановление

| Проблема | Изменение | Проверка |
| --- | --- | --- |
| OFF во время подготовки мог дождаться старого ON и запустить туннель | Намерение пользователя получает ревизию; OFF сразу отменяет запуск, а каждая асинхронная стадия проверяет актуальность | `control.check`, `tun.check`, `apply.check` |
| Быстрые ON → OFF → ON смешивали результаты разных запусков | Старое завершение не потребляет новое включение и не останавливает новый процесс | `control.check`, `stop.check` |
| Параллельные изменения профилей и маршрутов запускали устаревший план | Записи объединены общей последовательной очередью; OFF проходит немедленно | `control.check`, `apply.check` |
| Отказ подготовки повторного подключения мог оставить старое ядро работающим | Перед отказом выполняется подтверждаемая остановка | `control.check` |
| Переход в режим без туннельных маршрутов мог объявить idle при оставшемся ядре | Idle подтверждается остановкой; ошибка очистки не превращается в успех | `control.check` |
| Проверочный движок мог запуститься после начала TUN или остаться после смены профиля | Допуск проверяется повторно; подключение, замена и удаление дожидаются остановки обоих проверочных процессов | `catalog.check`, `control.check`, `stop.check` |
| Ошибка остановки теряла владение процессом или скрывалась повторным OFF | Объект процесса и журнал владения сохраняются до подтверждённого завершения; остатки остаются ошибкой | `stop.check`, `tun.check` |
| Устаревшие ответы контроллера и измерений меняли статус следующего запуска | Ответы привязаны к текущему процессу, API и ревизии; запросы отменяются; опрос не перекрывается | `live.check`, ревью `engine.ts` |
| Потеря локального контроллера выглядела как отказ всех удалённых узлов | Несколько неудачных опросов обозначают локальную проблему; успешный ответ восстанавливает локальный статус | `live.check`, ревью `engine.ts` |
| Сон/возобновление могли оживить вручную закрытый туннель | Ожидание сети и единственная попытка восстановления ограничены исходной ревизией; новый сон отменяет старое ожидание | `resume.check` |
| Ошибки PowerShell могли выглядеть как пустое, безопасное состояние сети | Снимки адаптеров/маршрутов завершаются ошибкой при неудаче запроса | `tun.check` |

### Реальный путь, DNS и сессии

| Проблема | Изменение | Проверка |
| --- | --- | --- |
| Рабочий запасной участник группы делал неисправный выбранный путь зелёным | Состояние вычисляется по фактически выбранному участнику; непроверенный путь показан как ожидающий проверки | `effective.check` |
| Переключение селектора оставляло старые входящие TCP/UDP-сессии на отказавшем пути | Для селекторов включено освобождение существующих соединений; приложение может установить их заново | `groups.check`, исходники закреплённого ядра |
| Переключение ради HTTP-задержки могло оборвать исправную игру | Авто не оптимизирует здоровый путь, пока на нём есть активные соединения; отказ по-прежнему разрешает переключение | `groups.check` |
| DNS группы наследовался от первого участника, даже если это частный resolver другого VPN | Общий resolver сохраняется только при совпадении у всех участников; иначе DoH идёт через выбранный путь группы | `groups.check`, `core.check` |
| Явное доменное правило «Напрямую» могло использовать DNS общего VPN | Такое правило теперь явно выбирает локальный DNS | `groups.check` |
| Обычный DNS Windows мог обходить TUN через параллельный интерфейс | Включён `strict_route`, проверенный по исходникам закреплённого Windows-ядра | `core.check`, `groups.check`; живая Windows ещё требуется |

`strict_route` создаёт фильтрацию на время работы ядра. Это **не отдельный постоянный kill switch**. После аварии процесса обычная маршрутизация Windows возможна. Обычный доменный DNS, собственный DoH приложения, IPv6 и сосуществование с другим VPN требуют отдельных живых проверок. Момент появления `/version` подтверждает готовность локального ядра, но не доступность удалённого Интернета.

### Импорт протоколов

- **Hysteria2:** сохраняется полная аутентификация `username:password`; проверяются параметры obfs.
- **Trojan/VMess:** неподдерживаемый транспорт не становится обычным TCP. Добавлен HTTPUpgrade; проверяются и сохраняются поддерживаемые TLS-параметры. Ошибочные cipher, alterId и verification-параметры не игнорируются.
- **Shadowsocks/TUIC:** исправлены проверки credentials/plugin и допустимых вариантов congestion control.
- **OpenVPN:** сохраняются TCP override у одиночного `remote`, IPv4/IPv6 family, направление или отсутствие направления `tls-auth`, `tls-crypt-v2`, значимые пробелы inline credentials, тип `verify-x509-name`, fingerprint и поддерживаемые ограничения сертификатов. TAP, внешние ключи, скрипты и неподдержанные ограничения не принимаются с потерей смысла.
- **VLESS/подписки:** исправлена проверка локальных IPv4-mapped IPv6; запрос соединяется только с предварительно проверенными адресами и не запускается после истечения срока ожидания DNS.
- В маскирование диагностических данных включены вложенные пароли obfs, массивы ключей и строки PEM.

Покрытие: `links.check`, `openvpn.check`, `vless.check`, `subscription.check`. Поддержка формата означает проверенное преобразование в конфигурацию, а не доказанное соединение с каждым поставщиком и каждой сетью.

### Интерфейс

- Публичный каталог действительно открывается; навигация ведёт в существующий экран.
- Исправлен порядок React hooks при исчезновении открытого маршрута.
- Ошибка preload в production больше не включает демонстрационный VPN. Ошибка загрузки даёт повторную попытку вместо бесконечной заставки.
- Поздний начальный snapshot не затирает более свежие события.
- Ошибки IPC видны; блокировки повторных действий снимаются при отказе; диалог не закрывается после несохранённой настройки.
- Сохранение маршрута и применение к ядру показываются отдельно. Ошибка применения companion-выбора не теряется при `saved:true`.
- Ручной EXE не исчезает после позднего завершения автоматического сканирования.
- В модальных окнах исправлены фокус, верхний Escape и возврат фокуса; списки поддерживают клавиатуру.
- При наличии только публичных профилей режим всего компьютера требует явного выбора подключения.

Статические проверки интерфейса и чистых функций выполнены. `test/ui.browser.mjs` содержит **12 сценариев настоящего DOM** с подставным IPC; сценарии и создание скриншотов подготовлены, но здесь **не исполнены**. Старые скриншоты в README не выдаются за проверку этой ветки.

## Обязательная приёмка перед Windows-релизом

Использовать отдельную Windows 10/11 VM и тестовые подключения. Сохранять снимки маршрутов/адаптеров до и после. Не запускать live-stress на рабочей машине.

| Сценарий | Критерий приёмки |
| --- | --- |
| ON/OFF, OFF во время старта, ON/OFF/ON; не менее 50 циклов | Не более одного своего core; после подтверждённого OFF нет своего TUN/маршрутов; последнее действие пользователя определяет итог |
| Wi-Fi → Ethernet → мобильная сеть, обрыв и возвращение сети | Нет петли через свой TUN; статус различает локальную и удалённую проблему; нет бесконечной череды перезапусков |
| Сон/гибернация, затем ручной OFF во время ожидания сети | Не более одного восстановления; OFF исключает последующий автоматический запуск |
| Отказ primary при активных TCP и UDP | После подтверждённого отказа выбран резерв; старая сессия освобождена; отдельно проверено переподключение приложения |
| Рабочая игровая сессия и более быстрый результат HTTP-проверки запасного | Активная исправная сессия не прерывается ради оптимизации |
| Удаление/замена используемого профиля и сбой записи | Нет самопроизвольного Direct/public; сохранение и runtime-результат отображаются отдельно |
| Подписка с ротацией адресов, одинаковыми именами, исчезнувшими записями | ID однозначных маршрутов сохранены; неоднозначные старые пути явно помечены, а не переназначены |
| Доменное Direct при общем VPN; private DNS разных провайдеров; IPv4/IPv6; DoH приложения | Проверен фактический DNS и путь трафика; отсутствуют заявления о защите, которую тест не подтвердил |
| Другой VPN, WSL/Hyper-V/VirtualBox, антивирусный lock | Чужие интерфейсы и настройки не изменяются; неподтверждённая очистка блокирует новый запуск |
| Принудительное завершение ядра и приложения, выход/выключение Windows | Журнал владения соответствует реальному процессу; восстановление не затрагивает чужой PID; отдельно зафиксировано поведение без независимого kill switch |
| DOM-сценарии + 900 px/обычное окно, клавиатура, высокий DPI | Выполнить `test:ui` с доступным Playwright и renderer-сервером; приложить новые скриншоты; ошибки и диалоги не перекрывают управление |

## Дальнейшие решения по приоритету

1. **Закрыть Windows-приёмку и реальные измерения в сетях РФ.** Нужны реальные данные по UDP, MTU, DNS и возврату сети; офлайн-модель этого не заменяет.
2. **Отдельно обновить закреплённое ядро**, после проверки совместимости и происхождения бинарников.
3. **Решить, нужен ли независимый kill switch.** Он требует отдельного проекта Windows WFP/firewall и аварийной приёмки; текущий переключатель и `strict_route` его не заменяют.
4. **Добавлять протоколы по проверенной потребности.** Сейчас полезнее точный импорт существующих форматов и понятная ошибка, чем ещё один пункт без подтверждённого сервера и UDP-поведения.

Новый сетевой оптимизатор, собственная relay-инфраструктура, multipath, общий reset Windows и массовый импорт произвольных конфигураций не включены в эти исправления.

## 2. Самый дешёвый полезный разрыв: fingerprint

В закреплённом upstream `common/tls/utls_client.go` есть **`chrome_155`**, а `chrome` идёт через `HelloChrome_Auto`. Закреплённый `utls-lx/u_common.go` разрешает Auto в **Chrome133**. Android `ProfileImporter.kt`, desktop `vless.ts` и `links.ts` не включают `chrome_155` в разрешённые значения. При этом VLESS без явно заданного `fp` в Waarp получает **Firefox**, а не Chrome. [P07][P08][L04][L05][L06]

Значит, правильная небольшая задача — разрешить и сохранить уже поддерживаемое значение, проверить его в конкретном бинарнике и показать как дополнительный вариант. Неправильно: заменить все сохранённые `chrome`, переписать дефолты или заявить, что все нынешние соединения используют устаревший Chrome.

Fingerprint — только одна часть поведения TLS. Нельзя отождествлять название пресета с полным поведением браузера, гарантированным обходом или качеством канала. Проверка должна сохранять проверку подлинности сервера, исходные ключи REALITY и совместимость транспорта. Не подбирать случайные SNI и не отключать верификацию ради зелёного результата.

**Критерий принятия:** импорт → сохранение → повторное чтение → JSON runtime → фактический pinned core → соединение с совместимым тестовым сервером. При несовместимости поле не теряется и не заменяется молча.

## 3. MASQUE: полезный дополнительный путь, не универсальное лекарство

В закреплённом sing-box-lx описан outbound `masque` для **CONNECT-IP**, а не только CONNECT-UDP. Он получает готовые ключи/адреса; регистрация WARP-устройства не происходит автоматически внутри core. Android importer пока не обеспечивает законченный пользовательский MASQUE-путь. [P06][L04]

Разделять четыре вещи:

1. **Семейство MASQUE** — HTTP-прокси-механизмы.
2. **CONNECT-IP** — перенос IP-трафика; RFC9484. [P23]
3. **WARP** — конкретная инфраструктура Cloudflare, условия и доверительная граница которой отдельны от Waarp.
4. **Реализация в движке** — конкретные поля и режимы, не универсальный JSON между Xray и sing-box.

Для закреплённого Cloudflare-профиля core документирует `vhttp=auto/h3/h2`; H3 использует QUIC/UDP, H2 — TCP. В `standard`-профиле нельзя автоматически предполагать тот же H2 fallback. Не подменять поле `vhttp` полем `network`. Доступность обычного сайта Cloudflare и открытый443 не являются успешной проверкой CONNECT-IP. [P06][P10]

**Предлагаемая интеграция:** сначала строго типизированный импорт подготовленного профиля, проверка ключей/адресов/режима и отображение в существующей карточке. Не обещать одну кнопку «получить бесплатный VPN» до отдельной проверки актуального способа регистрации, условий использования и хранения credentials. Не публиковать общий ключ в Git или каталог.

**Матрица приёмки:** H3 с разрешённым UDP; H3 без ответа; принудительный H2; auto при отказе H3; ошибочные ключи; недоступный endpoint; DNS; IPv4/IPv6; двунаправленная полезная передача; длительное соединение; отмена; OFF; смена физической сети. Неуспех не переключает защищённый маршрут на Direct. Без тестового доступа этап обозначается BLOCKED/NOT_RUN, а не «протокол работает».

H2 — независимый транспортный запасной вариант, но не независимый провайдер от H3/WARP. Для устойчивости нужен также доступный личный путь вне того же инфраструктурного отказа. Это архитектурный вывод, а не результат измерения всех Cloudflare-сетей.

## 4. Матрица возможностей: core не равен приложению

| Семейство | Что установлено на срезе | Что делать сейчас |
|---|---|---|
| WireGuard / AWG1–2 | Android импортирует нативный конфиг и параметры AWG1–2; основной пользовательский рабочий путь дома. [L04] | Сохранять рабочий исходник; текущий мобильный сбой отлаживать отдельно |
| AWG3/3.1 | Upstream документирует расширенные поля; Android importer их не принимает. Desktop-приёмка отдельных AWG3 полей не переносится автоматически на Android. [P11][L04][L02] | Отдельный тестируемый этап parity, только с сервером нужной версии |
| VLESS TLS/REALITY/XHTTP | Есть текущие мапперы; VLESS defaultfpFirefox. [L04][L05] | Расширить точечный fingerprint и сохранить согласованные серверные параметры |
| Hysteria2 | Android принимает базовый HY2 и Salamander, но список разрешённых query не даёт считать все upstream hopping-возможности реализованными. [L04][P13] | Сначала доказать UDP-доступность; расширять импорт только под реально предоставленный server config |
| TUIC | Базовый импорт уже есть. [L04] | Не добавлять повторно; проверить общие ограничения UDP, потерь, MTU и батареи |
| Trojan / VMess / Shadowsocks | Уже импортируются; Shadowsocks plugins нельзя считать поддержанными. [L04][L06] | Поддерживать существующие пользовательские варианты, не обещать все чужие схемы |
| MASQUE/WARP | Возможность в закреплённом core, пользовательский путь не доведён. [P06][L04] | Следующий ограниченный вертикальный проход, без смены всего core |
| NaiveProxy | Upstream использует Chromium networking; это не просто другое значение uTLS. [P12] | Оценить фактический Android build/runtime и сервер; отдельная следующая очередь |
| OpenVPN / OpenConnect / TrustTunnel | В проекте/ядре разные уровни поддержки; наличие build tag не является функциональной приёмкой. [L03] | Не создавать новую обещанную функцию до проверки exact binary + importer + server |
| Tor obfs4 / Snowflake / WebTunnel | Поддерживаемые Tor-проектом альтернативы с различными зависимостями. [P16] | Сначала совместимость/инструкция использования стороннего клиента, не второй VpnService внутри Waarp |
| XDRIVE | В Xray есть публичный эксперимент, но в прочитанном Waarp importer нет законченного пути. [P04][L04] | Изолированный R&D, не обязательное добавление второго core |
| Mimic / прочие beta-sidecars | У Hysteria Mimic требования Linux/root/eBPF с обеих сторон; чужой форк объединяет отдельные процессы. [P14][P05] | Не выдавать за безопасный переключатель на обычном нерутованном Android |

«Не проверено» здесь не означает «невозможно»; это означает отсутствие достаточного основания для пользовательской галочки «поддерживается».

## 5. Что заимствовать и что отвергнуть

### v2rayNG

Полезно: завершённая форма конкретного протокола, валидация URI и зависимых полей, скрытие неприменимых TLS-параметров, тест импорта и соединения. Не требуется переносить их навигацию, хранилище или модель жизненного цикла. [P02]

### WL-fork

Полезно: проверять реальный payload, сохранять задержку отдельно от пропускной способности, не уничтожать исходный config при нераспознанном расширении. Но README заявляет отключение проверки сертификатов для служебных HTTPS-загрузок; это **не переносить**. Не копировать «удалить нулевые»: временно недоступный личный профиль может оказаться единственным рабочим завтра. Не создавать временный второй WG/core параллельно текущему VPN. [P05]

### Outline / Psiphon

Outline Smart Dialer демонстрирует подбор транспорта/стратегии для существующего сетевого клиента; Psiphon — управляемые тактики. Для Waarp это ориентир на небольшую типизированную библиотеку вариантов и контроль совместимости, не повод автоматически заимствовать серверную инфраструктуру, весь SDK, лицензии или remote execution. [P15][P18]

### Оригинальный Amnezia

Опираться на фактические поля экспорта и совместимость с сервером. Дополнение шума и параметры формата пакета не взаимозаменяемы. Поля, которыми определяется формат, ожидаемый сервером, не генерировать случайно. Проверка исходным Amnezia на том же устройстве — полезный контроль, но одновременно включать два одинаковых peer identity на разных устройствах для такого сравнения нельзя считать чистым экспериментом. [P11][P22]

## 6. XDRIVE и будущие направления: отдельная полка экспериментов

XDRIVE использует облачный backend, но ему всё равно нужен удалённый сервер, выполняющий функцию выхода. В PR описаны зависимость от Google-аккаунта и API, дополнительные секреты, согласованные версии, возможные изменения протокола, задержка и собственные наблюдаемые сетевые признаки. Авторские измерения не становятся нашими. [P04]

Решение: оценивать только после основной стабильности, на отдельном аккаунте/стенде, с защитой tokens, квотами, удалением данных и явным предупреждением о зависимости от стороннего сервиса. Обычный пользователь не должен получить эксперимент скрытым обновлением рецепта.

QUICstep исследует перенос handshake через другой канал и последующую миграцию; это не отменяет необходимости доступного сетевого пути и поддержки миграции. CircumVolve, опубликованный 16.11.2026, предлагает автоматизированное исследование стратегий. Для нас полезен **лабораторный поиск с последующим review**, не исполнение сгенерированного кода на пользовательском устройстве. [F01][F02]

## 7. Порядок развития

**Сейчас:** проверить фактическую передачу и источник отказа, offline-диагностика, fingerprint155, убрать сдвиги от обычных уведомлений.

**Следом:** MASQUE через имеющийся core, совместимые рецепты поверх существующих Auto/памяти сети, недостающий разрешённый путь служебных загрузок.

**По результату реального запроса:** AWG3/hopping/NaiveProxy, каждый отдельно с interop-приёмкой.

**Не делать:** собственный криптопротокол, общий секретный публичный пул, trust-all TLS, массовый скан чужих IP, волшебный whitelist по SNI, автозамену всех рабочих конфигов, новый интерфейс ради количества функций.

# Waarp: глобальный корпус сетевых ограничений и план точечных улучшений

**Срез исследования: 17 ноября 2026 года.** Язык: русский. Назначение: рабочий материал владельцу и Claude/Opus для продолжения существующего приложения, а не задание переписать его.

## Решение в одном абзаце

Waarp должен выбирать **доказанно пригодный путь в текущей сети**, а не «самый современный протокол» или самый маленький ping. Сохранить существующие карточки, маршруты, Auto, владельцев фоновых работ и привычный UI. Ближайший объём: различать запуск VPN и работающий канал, проверять полезную передачу в обе стороны, открыть уже имеющийся `chrome_155` через корректный импорт, затем добавить управляемый MASQUE-профиль поверх существующего ядра. Не менять работающие конфиги автоматически, не снимать TLS-проверку, не обещать обход физического отключения или любого белого списка.

Это **предлагаемое продуктовое решение**, выведенное из исследования; новые функции в рамках этого документа не реализованы.

## Доказательства: пять разных категорий

| Метка | Значение | Чего она не разрешает утверждать |
|---|---|---|
| SOURCE | В исходнике/контракте есть функция или поле | Что оно доступно через UI и работает на сервере |
| MEASURED | Измерение с датой, сетью, целью и методикой | Что оно истинно для всей страны сейчас |
| UPSTREAM CLAIM | Заявление автора релиза или README | Что результат независимо воспроизведён |
| OWNER OBSERVATION | Наблюдение владельца на его устройстве | Что это межоператорная приёмка |
| PROPOSAL | Наше инженерное решение/гипотеза | Что оно уже реализовано или проверено |

Для любой новой возможности четыре обязательные ступени: **исходник ядра → импорт и сохранение → принятие фактическим бинарником → полезный трафик через реальный сервер**. UI-галочка, количество байтов, успешный TCP connect и даже handshake — не взаимозаменяемые доказательства.

Внешние источники приведены в [реестре](05-SOURCES.md). Новые сетевые замеры из РФ, Ирана, Мьянмы и других стран в этой работе **не выполнялись**. Ограничения источников, включая доступ только к индексированному тексту, отмечены отдельно.

## Что уже установлено для нашего проекта

**1. Быстрая точечная возможность.** В закреплённом core есть отдельный `chrome_155`; `chrome` разрешается в Chrome 133. Android importer `chrome_155` не принимает. При отсутствии `fp` VLESS-импорт использует Firefox: утверждение «весь Waarp сейчас ходит Chrome 133» было бы неверным. Это разрыв между core и importer, а не необходимость срочно менять весь движок. [P07](05-SOURCES.md#p07) [P08](05-SOURCES.md#p08) [L04](05-SOURCES.md#l04)

**2. MASQUE уже ближе, чем новый сторонний core.** Закреплённый upstream описывает Cloudflare-профиль с `vhttp=auto/h3/h2`. Android importer не предоставляет полноценный MASQUE import. Предпочтительнее довести путь core → importer → проверка → текущая карточка, чем переносить целый клиент v2rayNG. [P06](05-SOURCES.md#p06) [L04](05-SOURCES.md#l04)

**3. Не копировать WL-fork целиком.** Его проверка скачиванием полезна как идея. Но README точной beta заявляет trust-all для служебных HTTPS-загрузок. Это не приемлемая плата за доступность. Сохранить проверку цепочки/имени или строго определённую модель pinning; ошибка TLS не должна превращаться в успех. [P05](05-SOURCES.md#p05)

**4. Пользовательская проблема не диагностирована заочно.** Владелец сообщает: домашний Rostelecom с Amnezia работает, мобильный сценарий исследуется. Сообщение коллеги о TCP-доступности Cloudflare на Билайне — полезная гипотеза для теста, но не доказательство работоспособности WARP, UDP/H3 или длительного канала.

## Что исправляем в прежнем исследовательском контексте

Историческая версия `TZ-NEXT` на `4e0a2ef…` содержала категоричные страновые и протокольные формулировки. В текущем TZ часть уже смягчена. Не возвращать их в будущий код или тексты:

- «WG/OpenVPN/SS/Snowflake мертвы» заменить на результат конкретного пути, оператора, момента и версии.
- Числа попыток handshake, секунд блокировки и сроков жизни IP не превращать в общенациональные константы.
- Отличие DNS-ответов, низкая скорость и timeout не доказывают подмену, DPI или whitelist сами по себе.
- Доступность Cloudflare TCP не означает доступность WARP; домен в SNI не создаёт разрешённый внешний канал.
- Android уже в `main`; desktop-функция не считается автоматически реализованной на Android.
- Новизна Chrome 155/XDRIVE не означает долгосрочную нераспознаваемость.

## Полнота и честные пробелы

Глобальный охват построен в два слоя: углублённые страновые разборы и реестр географий с зафиксированными событиями/материалами. В качестве одного базового списка использован реестр Access Now за **2025 год**, опубликованный **31.03.2026**: 52 страны. Он не является картой текущих запретов; запись страны не устанавливает виновника, масштаб события или доступность протоколов. Добавлены географии измерительных исследований, не попавшие в этот исторический список. [G01](05-SOURCES.md#g01)

Нельзя обещать исчерпывающий live-аудит каждого оператора мира по открытым публикациям. Для географий без свежих сетевых данных стоит `UNKNOWN/RECHECK`, а не «работает» или «заблокировано». Любая страна вне реестра также **не считается свободной от ограничений**.

Рабочий критерий полноты — каждая проблема имеет диагностический путь, источник, область применимости и предел решения. Не количество протоколов и не количество галочек в настройках.

# Финальный аудит и условия выпуска stable — 16 ноября 2026

## Решение о версии

Текущий срез — **`0.4.1-rc.1`**, кандидат с исправлениями. **Выпуск с обозначением stable не утверждён.** Для него остаются обязательные проверки встроенного ядра и настоящей системной маршрутизации. Успешная сборка или зелёный unit-test не заменяет эти проверки.

Цель допуска — подтвердить конкретный контракт на указанной версии Windows, ядра и приложения. Конечный набор тестов не доказывает отсутствие всех возможных ошибок. В этом документе `PASS` означает только выполненный сценарий с сохранённым результатом; недоступный сценарий остаётся `BLOCKED` или `NOT RUN`.

Изменения запуска описаны в [STARTUP-RECOVERY](STARTUP-RECOVERY-2026-11-16.md), фактические результаты — в [VALIDATION](VALIDATION-2026-11-16.md). Артефакты каждого CI относятся к точному commit, который проверялся.

## Порядок работ и критерии

| Этап | Что проверяется | Условие завершения |
| --- | --- | --- |
| 1. Изучить | Код вызовов, журналы владения процессом, текущая документация, первичные исходники смежных клиентов и advisory зависимостей | Для каждого исправления названы нарушенный контракт и причина; догадки не выдаются за диагноз компьютера пользователя |
| 2. Собрать | Единый кандидат, закреплённые зависимости, перечень заявленных функций, воспроизводимые сценарии | Сборка относится к одному commit; приватные ключи, endpoint и конфиг отсутствуют в Git и артефактах |
| 3. Подготовить | Исправления и удаление доказанно неиспользуемого кода; бюджеты измерений определены до запуска | Изменения проверены по diff; обходов защиты процесса, сети и branch protection нет |
| 4. Сделать | Регрессии, измерения, повторные циклы, сборка EXE, фактическая сверка результатов | Все автоматические gates зелёные на финальном commit; ручные и сетевые блокеры отдельно закрыты доказательствами до stable |

## Удаление избыточного кода

- Удалены семь неиспользуемых импортов. В `tsconfig.json` включены `noUnusedLocals` и `noUnusedParameters`, включая тестовые файлы.
- Удалён `src/renderer/src/lib/cats.ts`: TypeScript-разрешение импортов от main/preload/renderer не находило путь к модулю, отдельный поиск не нашёл потребителей `Cat`, `catOf` и `CATS`.
- Добавлен `scripts/check-modules.mjs`: недостижимый production-модуль теперь останавливает `npm run check`. Проверка учитывает статические импорты, re-export и строковый `import()`. Она не претендует на доказательство отсутствия каждого неиспользуемого экспортируемого символа.
- Удалён невызываемый wrapper `RuntimeJournal.noUntracked`; вызывающие места используют подробный результат `inspectUntracked`.
- Удалено недостижимое состояние автоматического поиска в AddTunnel; ручной поиск сохранён.
- История задержек удалённых профилей очищается по принятому завершённому snapshot. Поздний ping удалённого профиля не создаёт её заново; неполный snapshot восстановления не стирает имеющиеся измерения.
- Старый stress-сценарий заменён ограниченным native runner: прежний сценарий не обеспечивал cleanup и мог напечатать `BAD`, оставив нулевой exit code.
- Упаковка `out/**/*` включала тестовые bundles и отчёты. Список ограничен main/preload/renderer; `package:verify` проверяет настоящий app.asar, наличие runtime/assets/notices, отсутствие тестов/отчётов и хеши упакованного ядра.

## Дополнительные найденные дефекты

**Мягкая остановка.** Между проверкой журнала и отдельным вызовом `AttachConsole(pid)` оставалось окно переиспользования PID. Helper теперь удерживает native Process.Handle и проверяет исходный путь и время создания непосредственно перед действием. При общей/недоступной консоли сигнал не отправляется. Engine ждёт graceful-окно только после подтверждения отправки; затем при необходимости завершает собственный child через его handle и проверяет выход. Обычный скрытый запуск Node с pipes не создаёт доступной консоли: обещать гарантированную мягкую остановку в этом режиме было неверно. Основание: [libuv process.c](https://github.com/libuv/libuv/blob/v1.51.0/src/win/process.c).

**Невозможно создать runtime-каталог.** Незащищённый `mkdirSync` в constructor мог остановить приложение до появления UI. Создание каталога перенесено в защищённую запись временного конфига, с диагностируемым отказом и без запуска core.

**Минимальная ширина окна.** Таблица публичных узлов имела внутреннюю прокрутку и скрывала ping/действие справа при 900 px. Компактная сетка сохраняет все столбцы; браузерная проверка требует полностью видимые и доступные для нажатия правые элементы без горизонтального scroll.

Независимый kill switch не заявлен и не реализован. После аварии ядра допустимый по текущему публичному контракту риск — прямой трафик через обычный маршрут Windows; UI обязан предупреждать об этом. Нельзя утвердить «защиту от всех утечек» тестами для другого контракта.

Отдельное архитектурное улучшение — проверка полностью сериализованного кандидата до остановки старого ядра с разделением сохранённого intent и применённого runtime. Оно описано в lifecycle-аудите и **не выдаётся за реализованную транзакционность**. Удерживать старый core после отзыва профиля нельзя: это нарушило бы запрет на использование отозванного пути.

## Правило утверждения

RC допускается к дальнейшей проверке после успешных автоматических gates на одном commit и проверки artifact hashes. Stable допускается только после закрытия всех обязательных блокеров с датой, ОС, версиями и сохранённым результатом. Непройденный или недоступный gate не превращается в PASS переименованием версии, повторным unit-прогоном или ручным обходом защиты ветки.

# MASQUE и подбор параметров подключения

## Что доступно

ПК и Android принимают подготовленный **MASQUE outbound в формате sing-box-lx** через существующий импорт текста, файла или буфера. Можно передать один объект, массив таких объектов или оболочку `{"outbounds":[...]}`. Это данные подключения: импорт не принимает произвольный runtime-конфиг, входящие listener, маршруты, файловые пути и `detour`.

Движки менять не требуется: общий набор полей проверен по закреплённым `option/masque_lx.go` — [ПК v1.14.2-lx.11](https://github.com/Leadaxe/sing-box-lx/blob/v1.14.2-lx.11/option/masque_lx.go) и [Android f1bac271](https://github.com/Leadaxe/sing-box-lx/blob/f1bac271853eaf13398ce1030c948aebc3aed2e1/option/masque_lx.go).

| Режим | Параметр | Необходимые данные |
| --- | --- | --- |
| Cloudflare WARP | `profile: cloudflare`, `vhttp: auto`, `h3` или `h2` | Адрес/порт, личный EC-ключ регистрации, закреплённый публичный ключ endpoint, внутренний IPv4 и/или IPv6 |
| RFC 9484 CONNECT-IP | `profile: standard`, `vhttp: h3` | Свой endpoint, его HTTPS URI CONNECT-IP, внутренние адреса и доверенный сертификат TLS |

`h3` использует QUIC/UDP; `h2` — HTTP/2/TCP. `auto` у Cloudflare пробует HTTP/3 с резервом HTTP/2 в том же движке. Два транспорта Cloudflare остаются одним провайдером, а доступность TCP к его адресу сама по себе не подтверждает работу туннеля. У `standard` HTTP/2 не реализован: интерфейс не предлагает фиктивный резерв.

**Регистрация WARP здесь не создаётся автоматически.** Нужен личный действующий экспорт. WireGuard-ключ WARP и ключ MASQUE — разные форматы. Для MASQUE приватный EC-ключ имеет формат SEC1 DER/base64, публичный ключ endpoint — SPKI DER/base64. Импорт проверяет структуру и допустимую кривую; это не доказывает, что регистрация разрешена удалённым сервером. Рабочие ключи не публикуются в примерах и не отправляются в диагностику.

Схема подготовленного Cloudflare-объекта (поля ключей намеренно не заполнены):

```json
{
  "type": "masque",
  "tag": "Мой WARP",
  "server": "АДРЕС_ИЗ_ЭКСПОРТА",
  "server_port": 443,
  "profile": "cloudflare",
  "vhttp": "auto",
  "private_key": "ЛИЧНЫЙ_SEC1_DER_BASE64",
  "public_key": "SPKI_DER_BASE64_СЕРВЕРА",
  "ip": "ВНУТРЕННИЙ_IPv4_ИЗ_ЭКСПОРТА",
  "mtu": 1280,
  "tls": { "enabled": true }
}
```

Этот шаблон с незаполненными полями не импортируется. Адрес, порт, ключи, URI и SNI берутся из действующей конфигурации. Подстановка случайных доменов или общих учётных данных не производится. Проверку сертификата/ключа нельзя выключить. Неизвестные поля отклоняются до сохранения, вместо тихого игнорирования параметров безопасности. Полный JSON Xray, V2Ray или sing-box с настройками приложения этим импортом не заменяется.

## Небольшой помощник в карточке туннеля

Перед проверкой показывается ограниченный список совместимых изменений. Это клиентский TLS fingerprint/разделение записей TLS, MTU WireGuard/AmneziaWG или режим HTTP у Cloudflare MASQUE. Для HY2/TUIC помощник не предлагает неподходящую фрагментацию TCP или uTLS. Ключи, адрес сервера, REALITY authentication, SNI и требующие согласования с сервером поля AWG не перебираются.

Проверка запускается пользователем при выключенном VPN. Это исключает одновременное использование одной peer identity активным туннелем и отдельным пробником. Исходная конфигурация проверяется первой. Рабочий исходник не заменяется из-за одной более низкой задержки. Изменение применяется явно, после проверки свежести результата и текущего профиля/сети; исходник доступен для возврата.

ПК уже хранит подбор отдельно и применяет его в соответствующей сети. Android сохраняет исходную конфигурацию рядом с явным выбором в существующем зашифрованном хранилище: отметка сети указывает, **где проводилась проверка**, и не является обещанием работы у любого оператора. Переход в другую сеть требует новой проверки. Автоматического скачивания рецептов и общих серверов нет.

`chrome_155` открыт в Android как явный вариант закреплённого core. Неуказанный VLESS fingerprint остаётся `ios`; сохранённый `chrome` не превращается в другой профиль. ПК сохраняет свой набор, поддерживаемый его более ранним бинарником. Списки/диапазоны портов Hysteria2 в ссылке обрабатываются одинаково; берутся только перечисленные сервером порты, без сканирования.

## Проверки

`test/masque.check.ts` проверяет импорт, отказ небезопасных/неподдерживаемых полей, отсутствие секретов в preview, неизменность оригинала и привязку подбора к свежим данным. На Windows он дополнительно вызывает `check` закреплённого engine; на другой ОС можно явно задать `WAARP_NATIVE_CHECK` с проверенным совместимым бинарником.

Android: `MasqueImporterTest`, `Hysteria2PortsTest`, `ProfileTuningTest`, существующие `ProfileImporterTest`/`OpenVpnImporterTest`. `OperationFeedbackInstrumentedTest` проверяет отсутствие сдвига следующей кнопки при повторных успешных действиях, включая увеличенный шрифт; ошибки остаются видимыми рядом с действием.

Parser/JVM/config-check не означают успешное подключение к живому WARP. Для сетевой приёмки отдельно нужны действующая личная регистрация, полезная передача данных в обоих направлениях и проверка на конкретной сети. Без таких данных результат остаётся `NOT_RUN`.

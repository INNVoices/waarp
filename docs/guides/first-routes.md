# Первый маршрут: приложение, затем домен

Здесь мы настроим один личный профиль, направим через него выбранное приложение, а затем отдельно проверим правило для домена. Два опыта помогают понять, какое правило действует, и получить полезный отчёт, если соединение не работает.

Waarp — клиент VPN и прокси. Для этого сценария нужен профиль вашего сервера или провайдера, которому вы доверяете. Само приложение не выдаёт личный VPN-сервер. Каталог публичных узлов для первого опыта не нужен: ответ стороннего узла подтверждает доступность в момент проверки, но не его владельца или политику обработки трафика.

## Какую сборку открывать

Актуальная загрузка — **preview 1.0.0 для Windows и Android**, [preview-2026-11-22-r2](https://github.com/INNVoices/waarp/releases/tag/preview-2026-11-22-r2), проверено **2026-11-22 18:51:59 UTC**. Windows EXE не имеет подписи издателя; Android APK подписан debug-ключом и устанавливается как `local.waarp.android.debug`. Сертификат всех трёх APK отличается от r5: обновление поверх старого приложения невозможно. Для первой установки нужно устройство без r5; сохраните прежнюю установку и её данные. Новые изменения `main` не появляются в уже скачанном файле. [Загрузки, ABI и SHA-256](../INSTALL.md#downloads) · [состояние выпусков](../RELEASES.md#published-preview-2026-11-22-r2).

Ссылки на интерфейс и правила r6/r5 ниже — исторические пояснения, на которых основан walkthrough. Обновление ссылок загрузки не является новым device test всех шагов этого руководства.

Инструкция опирается на интерфейс и правила опубликованных preview, а также на текущую документацию. Она не является отчётом о новом испытании на физическом устройстве. Если подпись кнопки в вашей сборке отличается, запишите её версию и сверяйтесь с документацией этого выпуска.

## Перед первым включением

1. Установите файл для своей системы по [инструкции](../INSTALL.md) и сравните полный SHA-256 с тем же релизом. Android APK разных ABI — альтернативы: устанавливается один подходящий файл.
2. Подготовьте **один** личный профиль. Назовите его, например, «Мой сервер». Не публикуйте конфигурацию, ключи или ссылку подписки. Если сервер различает устройства по ключу, используйте отдельный профиль для этого устройства.
3. Выберите обычную HTTPS-страницу, которую разрешено открывать через этот профиль. Для проверки конкретного сервиса используйте его реальный адрес. Для точного сравнения выходного адреса удобен ваш HTTPS-сервер с журналом запросов; это дополнительная проверка, а не условие первого запуска.
4. С выключенным Waarp откройте эту страницу в выбранном приложении и запишите, открылась ли она. Это исходное наблюдение для текущей сети.
5. Проверьте, нет ли другого активного VPN или полного маршрута через другой TUN. Сначала остановите либо согласованно перенастройте конкурирующий VPN. Сетевые настройки организации меняйте только в пределах своих прав.

Для первого опыта оставьте одну включённую карточку и один выбранный профиль. Автоматический выбор, группы и резерв добавляйте после проверки этого простого случая.

## Windows: направить один браузер через личный профиль

1. Откройте **«Подключения» → «Добавить конфиг»** и импортируйте подготовленный профиль. Убедитесь, что он появился в сохранённых подключениях.
2. Выберите режим **«Только карточки»**. В этом режиме общий путь остаётся обычным; выбранные карточки задают исключения. Запишите, включены ли отдельные исключения для локальной сети или российских доменов: они могут влиять на выбранную цель.
3. В **«Маршрутах»** добавьте браузер. Выберите именно его исполняемый файл, а не сайт или ярлык. В выборе пути откройте **«Выбрать сервер» → «Сохранённые»** и выберите «Мой сервер». При добавлении новой карточки выбор подключения создаёт маршрут — проверьте появившуюся карточку.
4. Включите главный переключатель Waarp. Для создания Windows-туннеля нужны права администратора. Если приложение сообщает об этом, запустите проверенный EXE через **«Запуск от имени администратора»** и прочитайте системный запрос.
5. Создайте новое соединение в выбранном браузере: например, заново откройте тестовую страницу после закрытия прежних соединений. При необходимости полностью завершите и снова откройте браузер, предварительно сохранив работу. Уже открытая вкладка и её кэш не подтверждают новый сетевой запрос.
6. Сопоставьте результат страницы с путём карточки и доступными записями соединений/диагностики. Если ваш сервер ведёт журнал, сопоставьте время и выходной адрес **этого** запроса. Не публикуйте сырой журнал с личными адресами.

Правило приложения действует на подходящие процессы, поэтому в первом опыте оно относится к браузеру, а не к одной вкладке. Для контрольного сравнения временно выберите в этой карточке **«Напрямую»**, снова создайте соединение и запишите результат. После сравнения верните личный профиль. Если оба пути успешно открывают страницу, это нормальный результат; сам факт загрузки ещё не различает пути. [Выбор сервера](../SERVER-SELECTION-2026-11-18.md) · [интерфейс r6](https://github.com/INNVoices/waarp/blob/preview-2026-11-18-r6/src/shared/strings/ru.json).

## Android: выбрать одно установленное приложение

1. Откройте **«Туннели»** либо **«Добавить туннель»** на главном экране и импортируйте личный профиль. Импорт сам по себе не включает VPN и не назначает маршруты.
2. На главной странице выберите **«Только выбранное»**.
3. Откройте **«Маршруты» → «Добавить маршрут» → «Приложение»**, найдите тестовое приложение по имени или package name. В **«Основном пути»** выберите «Мой сервер», оставьте маршрут включённым и нажмите **«Сохранить маршрут»**. Выбор в карте/списке внутри формы остаётся черновиком до сохранения.
4. Включите Waarp и подтвердите системный запрос **VPN**. Отказ в разрешении не является проверкой сервера: сначала нужно разрешение на создание локального VPN. Во время работы сервиса Android показывает постоянное уведомление.
5. Откройте тестовую страницу из выбранного приложения, создавая новое соединение. Сравните фактический результат с маршрутом и диагностикой. Для контрольного опыта явно выберите в форме прямой путь, сохраните маршрут, повторите запрос, затем верните личный профиль.

Android применяет правила к UID. Приложения с общим UID не могут получить независимые пути. Если Android не определит приложение, защищённый режим выбранных приложений может блокировать соединение без отдельного совпавшего правила. Общий DNS Android тоже не всегда содержит сведения о приложении; при конфликте нескольких защищённых путей используйте объяснение в интерфейсе и [раздел Runtime policy](../ANDROID.md#runtime-policy). Поэтому первый опыт использует один профиль. [Форма маршрута r5](https://github.com/INNVoices/waarp/blob/preview-2026-11-18-r5/android/app/src/main/java/local/waarp/android/ui/HomeRoutes.kt).

Preview установлен как **`local.waarp.android.debug`**; production-пакет — **`local.waarp.android`**. Один не обновляет другой. Если Android сообщает о конфликте подписи, сохраните текущую установку и выясните происхождение APK; не удаляйте приложение только ради обхода конфликта. [Обновления и подписи](../INSTALL.md#updating-and-signatures).

## Второй опыт: только выбранный домен

Сначала выключите правило приложения, использованное выше. На обеих платформах правило приложения имеет приоритет перед более общим правилом назначения: оставленная карточка браузера помешает отдельному опыту с доменом. На Windows также учитываются явные глобальные исключения. [Правила Windows r6](https://github.com/INNVoices/waarp/blob/preview-2026-11-18-r6/src/main/awg.ts) · [правила и пояснения Android r5](https://github.com/INNVoices/waarp/blob/preview-2026-11-18-r5/android/app/src/main/java/local/waarp/android/ui/HomeRoutes.kt).

1. Оставьте режим **«Только карточки»** на Windows или **«Только выбранное»** на Android.
2. Добавьте маршрут типа **«Адрес»**. Введите реальный домен тестовой страницы, например `example.com`, заменив пример своей целью. Не вставляйте в поле домена путь `/account`, пароль или ссылку подписки. Доменное правило включает поддомены, но не произвольные сторонние домены.
3. Назначьте «Мой сервер». На Android подтвердите **«Сохранить маршрут»**. На Windows проверьте созданную карточку после выбора подключения.
4. Создайте новый запрос к этому домену. Проверьте отдельно другую страницу, которая не совпадает с правилом и не попадает под другие карточки. Запишите оба результата и выбранные пути.

У одного сайта могут быть отдельные домены для входа, API, изображений или видео. Загрузка главной страницы не доказывает, что все эти запросы пошли тем же путём. Добавляйте только известные необходимые адреса по одному либо осознанно выберите правило всего приложения. Для произвольного EXE Waarp не может вывести нужный домен из имени программы.

## Если результат непонятен

Откройте **«Проверить соединение»** у маршрута и укажите реальный адрес. На Windows доступно также расследование в **«Диагностике»**. Сначала прочитайте наблюдаемый этап: DNS, TCP, TLS или HTTP. Отмена или отсутствие измерения не означают отказ сервера. Рекомендация не применяет новый путь без вашего действия; на Android выбор рекомендации в форме ещё нужно сохранить. [Подробности проверок](../CONNECTION-TOOLS.md#проверить-конкретную-программу-или-маршрут).

| Наблюдение | Что оно позволяет сказать | Следующий шаг |
| --- | --- | --- |
| Waarp показывает ON | Локальный VPN запущен | Отдельно открыть целевой ресурс |
| Проверка получила HTTP(S)-ответ | Этот адрес ответил по проверенному пути в это время | Проверить реальное действие в приложении |
| Страница открылась, путь в отчёте неизвестен | Подтверждена загрузка страницы | Сопоставить новую запись соединения или контролируемый серверный журнал |
| Есть время ответа | Измерено время данной HTTP(S)-проверки | Не считать его игровым ping, скоростью загрузки или качеством звонка |
| Изменился выходной IP одного запроса | Изменился наблюдаемый выход этого запроса | Не переносить вывод на DNS, все приложения или всю сессию |
| Один профиль не отвечает | Эта проверка не удалась | Сохранить этап и ошибку; проверить профиль и сеть, не менять несколько настроек одновременно |

Если переключение пути разорвало старое соединение, повторите действие в приложении. Сохранение одного TUN не гарантирует перенос уже существующей TCP-, игровой или голосовой сессии между серверами.

## Закончить опыт и сообщить о проблеме

Выключите **главный переключатель** Waarp и дождитесь завершения остановки. Закрытие окна Windows может лишь спрятать приложение в трей. Затем создайте новый запрос и сравните его с исходным наблюдением. OFF не означает постоянную блокировку обычной сети: у Windows нет отдельного firewall kill switch, а блокировка соединений вне VPN на Android зависит от системной настройки lockdown. [Ограничения жизненного цикла](../RELIABILITY.md) · [Android VPN](https://developer.android.com/develop/connectivity/vpn).

Для [сообщения о маршрутизации](https://github.com/INNVoices/waarp/issues/new?template=routing.yml) достаточно воспроизводимого описания:

```text
Файл и версия: точное имя скачанного EXE/APK
Система: версия Windows или Android/API; ABI, если известен
Опыт: приложение / домен; один личный профиль; общий режим
Ожидалось: какой запрос должен был идти по какому пути
Получилось: результат запроса, состояние Waarp, этап и текст ошибки
Контроль: результат с выключенным Waarp и с явно выбранным Direct
Другой VPN: нет / да / неизвестно
Повтор: воспроизводится / не воспроизводится / не проверялось
```

Перед отправкой удалите ключи, профили, токены, ссылки подписок и личные адреса. Если этап не проверялся, так и напишите. Подробности уязвимости направляйте по [SECURITY.md](../../SECURITY.md), а не в публичный issue.

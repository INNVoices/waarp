### Исправления по результатам проверки

1. **Э0.1:** OFF-замеры теперь публикуются через `Engine.recordIdlePings` с той же монотонной последовательностью раундов, что ON. Копии status не создают точки; равное численное значение в следующем раунде создаёт новую. Старые профили не возвращаются в историю.
2. **Э0.2:** отказ атомарной замены не приводит к прямой перезаписи рабочего файла. Успех проверяется отдельно для каждого изменённого физического rule-set через маркер внутри этого же файла; один общий canary-файл больше не подтверждает остальные watcher. Запросы маркеров имеют локальный DNS-ответ/отказ. Общий предел — 3 секунды, до 8 одновременных ACK; неподтверждённый файл или смена поколения не дают успешный apply. Закрытие соединений сравнивает старое и новое эффективное первое правило, включая порядок, удаление, списки, CIDR и приоритет приложений; незатронутые сессии сохраняются. DELETE учитывается только после успешного HTTP-ответа актуального core.
3. **Э1:** общий deadline включает слои Direct, HEAD→GET, личные пути и проверку актуальности сети. Отмена закрывает запросы и принадлежащий заданию checker; изменение master intent отменяет диагностику сразу. Применение связано с выданным main токеном, измеренным личным профилем, его содержимым, сетью, runtime-контекстом и пятиминутным сроком. Непроверенный путь, изменённый профиль, новая сеть или старый ответ не меняют карточку/память. Ошибка применения сохранённого маршрута видна пользователю. Redirect и ответ API задержки не объявляются открывшейся страницей; неподдержанная схема URL отклоняется.
4. **Э2:** включённая Direct+DPI-карточка сама требует core, даже без туннельного профиля. Переход с последнего туннельного маршрута на Direct+DPI не переводит приложение в ложный idle.
5. **Э3:** checker принадлежит одному заданию на всю последовательность `ensure → probe`, поэтому фоновый OFF-замер не подменяет ручной подбор. Отмена/60-секундный deadline ждут остановку; недоступный checker не считается провалом исходного профиля. Применяется только действительно успешный совместимый вариант после неуспеха исходника; сохранённые варианты проверяются повторно. TCP/uTLS-варианты не предлагаются Hysteria2/TUIC. Сеть проверяется при запуске и существующим watch; смена действующего overlay вызывает один контролируемый reconnect. Обычная правка карточки использует сетевой контекст текущего runtime без дополнительных PowerShell-запусков. Ошибка сохранения не публикует вариант, ошибка reconnect не выдаётся за успешное применение; сброс доступен и для сохранённого неактивного подбора.
6. **Э4:** HY2 отвергает пустые элементы списка портов. AWG отвергает пустой/нулевой `HeaderProtectionKey`, сохраняет явно выключенные флаги; сохранение/чтение и маскирование ключа покрыты регрессиями. Условные бинарные проверки явно печатают SKIP. CI повторяет `links` и `awg-import` **после** `engine:fetch`, как уже делалось для `slots`.
7. **Э5:** конфиг для просмотра скрывает дополнительные секретные поля и произвольные заголовки. Общий диагностический экспорт строится из разрешённых полей: обезличенные связи профилей/карточек, состояния, замеры и счётчики журнала. Он не включает исходные тексты логов, endpoint, имена, личные пути, подписки и ключи. Для истории, диагностики, отмены, технического блока и ширины 900 px добавлены сценарии существующего UI harness.
8. **Э6:** повреждённый смешанный список отклоняется целиком; `full:` не превращается молча из точного домена в суффикс. Первый формат — доменные суффиксы, `domain:`, `*.`/`.` и комментарии. Новый снимок сохраняется до публикации в runtime; сбой записи/загрузки сохраняет прошлый. Поздняя загрузка не восстанавливает удалённый источник и не отменяет выключение. Сетевая загрузка не держит очередь маршрутов; суточная проверка работает в течение всей сессии, без циклических повторов ошибки.
9. **Э8:** идентификатор публичного узла закреплён за эффективным конфигом и не меняется при перестановке источников/перезапуске. Неуспешное обновление восстанавливает и снимок, и карту конфигов. Явное добавление изменившегося узла не возвращает старый личный профиль только из-за совпадения id. Короткие заголовки «Страна»/«Ответ» помещаются в существующие колонки; подсказки прямо объясняют происхождение страны и характер HTTP-замера.

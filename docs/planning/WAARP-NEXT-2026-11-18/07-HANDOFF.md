Этот документ сохраняет состояние на момент завершения подготовительной части. Разрешением на последующую реализацию стала команда владельца, а не окончание чужого CI или автоматический запуск.

## 2. На каком коде основаны выводы

Исходный remote main: [f66e5def3d689837db010c3453086a832c701fcc](https://github.com/INNVoices/waarp/commit/f66e5def3d689837db010c3453086a832c701fcc), tree `37421f5f5bffbea0391a39719ea7185923925897`. Его Git tree сопоставлен с изолированным локальным снимком. Незакоммиченные файлы соседнего исполнителя не включались в исходный код подготовки.

Перед сохранением повторно прочитан main: [d7b1a9fd93557de7093ddc606dcefb3590da51d2](https://github.com/INNVoices/waarp/commit/d7b1a9fd93557de7093ddc606dcefb3590da51d2), tree `d8ab8859af9c966988fc32f2672936c362cc73e5`. [Сравнение с исходным срезом](https://github.com/INNVoices/waarp/compare/f66e5def3d689837db010c3453086a832c701fcc...d7b1a9fd93557de7093ddc606dcefb3590da51d2) содержит ровно два коммита и два файла:

- новый `docs/ANDROID-CHAMELEON-2026-11-18.md` — самостоятельное исследование точки входа Android;
- добавленную ссылку на него в `docs/README.md`.

Исходники приложения, версии engine, существующие UI-компоненты и тесты этим продвижением не изменены. Chameleon сохраняет статус отдельного концепта и не включается в ближайшую очередь Atlas/подбора/непрерывности. Существующие ссылки на код указывают на исходный SHA намеренно; они не маскируются под будущий main.

GitHub API на момент сохранения сообщает `visibility: private`, default branch `main`. Внешняя открытая контрибуция ещё не доступна как у публичного проекта. WN-07 готовит форматы и примеры; этот пакет не меняет видимость репозитория и не считает публикацию уже выполненной.

Наблюдения по старым и соседним скриншотам имеют отдельное происхождение в UX-документе. Они пригодны для анализа структуры и проблем, но не подтверждают новую сборку и не заменяют приёмку после реализации.

## 3. Границы записи в Git

Изменение ограничено этим каталогом `docs/planning/WAARP-NEXT-2026-11-18/` и одной навигационной строкой в `docs/README.md`. Существующие материалы и ссылка на Chameleon сохраняются. В коммит не входят продуктовый код, dependency/engine locks, CI, release manifest, сборки, ключи, пользовательские конфигурации или результаты чужого незавершённого теста.

Сохранение выполняется новым обычным коммитом поверх прочитанной актуальной головы. Передвижение main должно проверять ожидаемый SHA; при изменении головы требуется перечитать изменения и повторить наложение документации. Force-push и замена дерева старым снимком недопустимы.

Для этого docs-only коммита используется стандартная пометка `[skip ci]`: сетевые и Android сборки не проверяют текст ТЗ и не должны конкурировать с текущим preview. Workflow и его условия не редактируются. Пометка не распространяется на будущую реализацию: код проходит действующие проверки проекта.

## 4. Что проверено, а что остаётся будущей работой

Подготовительный контроль: существование ссылок на локальные файлы и закреплённые исходники, диапазоны строк, валидность JSON, согласованность WN-зависимостей и статусов, отсутствие изменений вне документации и проверка пробельных ошибок. Итог сохранения подтверждается коммитом и сверкой удалённых blob SHA с подготовленными файлами. В подготовительном прогоне валидны все 4 JSON, 9 задач ожидания и их зависимости; сверены 32 хеша опорных файлов, 102 относительные ссылки и 133 вхождения ссылок на закреплённый код. Ошибки диапазонов строк и ссылочных обозначений исправлены до сохранения.

|---|---|
| Чтение репозитория, существующего исследования и текущих точек интеграции | Выполнено |
| Чтение первичных upstream sources / документации | Выполнено; реестры источников приложены |

Значения p95, размеры контрольных каталогов и ресурсные ограничения в плане — предложенные критерии экспериментов. Они не являются измеренными результатами Waarp, обещанием переключения за микросекунды или подтверждением готовности любого игрового протокола.

## 5. Что делать после команды владельца

1. Начать с WN-00: прочитать актуальный main, изменения соседнего исполнителя, текущие инструкции репозитория и состояние завершённого preview. Сравнить затронутые файлы с `baseline.json`.
2. Обновить изменившиеся предположения. Уже существующие функции не переписывать заново и не воспроизводить всё исследование, если соответствующий код не менялся.
3. Зафиксировать владельцев общих файлов и узкий результат первого изменения. Основной native owner, Android `MobileRepository`, live apply и общие types не редактируются конкурирующими исполнителями одновременно.
4. Выполнить нужные ограниченные WN-01 проверки. В первую очередь подтвердить реальные API/путь тестового трафика, селекторы и старые workers; карту проверить с локальными данными в текущих оболочках.
5. Реализовывать по зависимостям WN-02…WN-07. Каждый вертикальный сценарий включает UI/UX и проверку результата. Не откладывать отмену, возврат, пустые состояния, сохранение выбора и footer до конца сетевой разработки.
6. Community Atlas остаётся WN-08 с отдельным конкретным решением о сервисе и добровольных данных. Он не блокирует выпуск локальной карты.

Предпочтительная первая продуктовая цепочка: карточка приложения → существующая проверка с контекстом → понятное наблюдение → проверяемая рекомендация → нынешний механизм сохранения/применения. Карта читает те же данные и использует тот же выбор. Мягкое улучшение бережёт разрешённую текущую сессию; строгая политика не сохраняет запрещённый путь.

До команды владельца следующий статус — ожидание. Не запускать автоматический polling соседнего чата/CI, не менять приложение и не трактовать готовность этого пакета как разрешение на разработку.

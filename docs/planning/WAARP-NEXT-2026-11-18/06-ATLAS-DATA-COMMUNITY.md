# Atlas: данные, карта и дальнейший коллективный слой

**Статус:** проектное решение, WAIT_OWNER_START. Приложение, источники и сетевые настройки этим документом не изменяются. UX размещения описан в [02](02-UX-INTEGRATION.md), владельцы операций — в [04](04-TECHNICAL-SPEC.md).

## 1. Продуктовый результат

Карта отвечает на три вопроса: какие подключения доступны, что известно об их пригодности для выбранной задачи и какой путь фактически выбран. Она показывает устройство → выбранный выход → известную цель, когда эти сведения есть. Линии обозначают **логические связи**, не географический маршрут кабелей или перечень маршрутизаторов.

Карта не является второй библиотекой серверов. Личный список, публичный каталог, группы и карта используют одни ID, единый поисковый запрос, одинаковые правила свежести и один механизм применения. Выбор точки только выделяет её и открывает существующие сведения. Он не меняет сеть. Исходная логика каталога: [catalog.ts](https://github.com/INNVoices/waarp/blob/f66e5def3d689837db010c3453086a832c701fcc/src/main/catalog.ts), [CatalogPool](https://github.com/INNVoices/waarp/blob/f66e5def3d689837db010c3453086a832c701fcc/src/main/catalog-pool.ts).

## 2. Откуда брать сведения

| Сведение | Источник первой версии | Что разрешено утверждать |
|---|---|---|
| Наличие сервера | Существующий личный профиль или сохранённый публичный кандидат | Профиль сохранён; работоспособность ещё не следует |
| Свежая проверка | Текущее наблюдение с контекстом сети, профиля, метода и времени | Конкретная проверка выполнена в данном контексте |
| HTTP latency | Существующая HTTP-проверка и новая общая модель наблюдений | Время этой HTTP-проверки, не игровой ping |
| TCP/TLS | Поддерживаемый adapter к выбранному outbound и цели | Успех/отказ соответствующего этапа, не вход в приложение |
| UDP, потери, jitter | Только протокольно корректный тест или подтверждённые наблюдения потока | Предел относится к измеренной цели/методу; отсутствие возможности — «не проверено» |
| Страна из названия | Существующий countryOf / импортированные метки | «Регион указан источником»; не точная координата сервера |
| Координаты IP | Локальный GeoIP dataset с версией и источником | Приблизительное местоположение указанного публичного IP |
| Загрузка сервера | Только доступный доверенный показатель сервера с временем | В первой версии обычно «нет данных»; latency не превращать в загрузку CPU |
| Пользователь | Локально выбранный регион; подтверждённое приблизительное определение по явному действию | «Ваш регион, приблизительно»; не GPS и не адрес человека |
| Цель приложения | Подтверждённый endpoint из известных правил/контекста, если доступен | Выбранная цель; не обещание полного списка игровых серверов |

В исходном Windows коде countryOf читает флаг/название/код страны и прямо отмечает отсутствие GeoIP DB. CatalogNode не содержит координат, ASN, UDP-качества или загрузки. Это новые данные, которые надо получить честно; нельзя заполнить их декоративными значениями. [countryOf и CatalogNode](https://github.com/INNVoices/waarp/blob/f66e5def3d689837db010c3453086a832c701fcc/src/main/catalog.ts#L31-L91).

## 3. Минимальный стек и offline

**Выбор для реализации после проверки зависимостей:** MapLibre GL JS в существующем Electron renderer; MapLibre Native в существующем Android UI. Для первой версии достаточно штатных GeoJSON-, circle-, symbol- и line-слоёв. deck.gl не является обязательной зависимостью: добавить его только при конкретном неудовлетворённом сценарии и измеренном преимуществе. [MapLibre sources](https://maplibre.org/maplibre-style-spec/sources/), [кластеризация](https://maplibre.org/maplibre-gl-js/docs/examples/create-and-style-clusters/).

Первый Atlas получает локальную облегчённую геометрию мира, локальный style и необходимые ресурсы подписей. Кандидат основы — Natural Earth, чьи опубликованные условия относят наборы карты к public domain. Перед включением зафиксировать именно выбранный архив, checksum, происхождение и соответствующие notices. Данные карты и лицензия MapLibre учитываются отдельно. [Natural Earth](https://www.naturalearthdata.com/about/terms-of-use/).

Решение первой версии:

1. Контуры мира и крупные регионы доступны без сетевых тайлов, без токена картографического провайдера и без CDN.
2. Точки с подтверждённой приблизительной геолокацией отображаются как точки; метки страны без координат — как региональные группы с явной пометкой источника.
3. Неизвестная география остаётся в списке «Регион не определён» и доступна для поиска и выбора. Не помещать её в точку 0,0.
4. Масштаб ограничивается полезной детализацией данных. Уличная карта не нужна для выбора сетевого узла.
5. Детализация IP-географии — отдельный локальный dataset. Предварительный кандидат DB-IP Lite: официальный источник предоставляет CSV/MMDB, ежемесячные обновления и CC BY 4.0, отмечая уменьшенные покрытие и точность. Файл и reader выбираются в короткой проверке WN-01; полная база автоматически в APK не добавляется. [DB-IP Lite](https://db-ip.com/db/lite.php), [FAQ](https://db-ip.com/faq.php).
6. Обновление dataset проходит существующий служебный transport и лимиты, с сохранением последней валидной версии. Просмотр карты не запускает загрузку базы.

Это законченный первый продукт: работающий каталог с географическими группами и известными точками. Более точная география постепенно улучшает его, но не блокирует работу.

Проверка геобазы до выбора версии: покрытие IPv4/IPv6, размер установленного набора и RAM, скорость фонового lookup, возможность одинаковых ответов на двух платформах, атрибуция, атомарная замена, отсутствие удалённого вызова на каждый endpoint. Конкретный reader не назначать по одному названию: подтвердить поддерживаемые форматы и лицензию его версии. Если этот эксперимент не проходит бюджет, оставить региональные группы; не писать собственный формат IP-диапазонов.

## 4. «Вы на карте» без ложного определения

Публичный IP, полученный через текущий VPN, обычно относится к выходу VPN. Он не устанавливает местонахождение устройства. Нельзя поставить точку «Вы» рядом с выбранным выходом только потому, что проверка выполнена через него.

Приоритет:

- Сохранённый самим пользователем регион — основной offline-вариант.
- Однократно определённый приблизительный регион при разрешённом способе проверки — дополнительный вариант с указанием источника.
- Когда нет данных, отдельный нейтральный якорь «Ваше устройство» без географической точки. Никаких выдуманных координат.

GPS, фоновое определение точного местоположения и запрос разрешения геолокации при первом открытии не нужны. Защищённая политика не разрешает обход VPN прямым IP-запросом ради карты. UI может предложить выбрать регион; функция продолжает работать без него.

В поле «рядом» различать географическую близость и качество соединения. Сортировка по расстоянию никогда не является рекомендацией лучшего маршрута.

## 5. Данные и идентичность

Карта получает отдельное представление данных, не исходный outbound JSON. Имена полей ниже — проектный контракт; окончательные типы согласовать с [04](04-TECHNICAL-SPEC.md).

| Объект | Обязательные поля/смысл | Запрещённая подмена |
|---|---|---|
| Узел | Стабильный локальный ID, тип personal/public/group, связь с существующим профилем | Новый ID при каждом refresh, отдельный импорт для карты |
| География | precision: unknown/country/approximate-point; provenance; datasetVersion; время определения | Координаты по придуманному названию города |
| Путь | scope приложения, подтверждённый active route, отдельно pending selection и drain-старый путь | Выбранный в UI путь как уже применённый |
| Наблюдение | Метод, цель, context сети, профиль/ревизия, runtime generation, время/срок, результат, объём выборки | Один общий ping для всех приложений/сетей |
| Пригодность | Уровень доказательности и объяснение ограничений; политика профиля | Универсальная оценка 99/100 без методики |
| Снимок | Монотонная revision, полный список/дельта в лимитах, счётчики eligible/known/unknown | Полная перезагрузка всей геометрии каждую секунду |

Один DNS hostname может иметь несколько адресов; проверки могут закрепляться на одном IP. География должна относиться к реально использованному адресу, а не случайному результату нового DNS-запроса. При anycast/CDN координата остаётся оценкой. Смену адреса и контекста следует отражать, а не переносить старый «зелёный» результат на другой узел.

Ключи, подписки, реальные credential fingerprints, секретные заголовки и полные конфиги не нужны карте. Даже если host уже отображается в существующей библиотеке, его наличие в локальном UI не разрешает отправлять его картографическому поставщику или Community.

## 6. География, признаки состояния и измерения независимы

Географическая позиция, доверие к источнику и свежая работоспособность — разные оси.

- Зелёный статус означает только описанную свежую успешную проверку.
- Сохранённый кандидат без проверки не становится красным и не считается отказавшим.
- Старое измерение видно как история, не как текущая оценка.
- «Публичный» обозначает происхождение и границу доверия; высокий рейтинг доступности не означает безопасность оператора.
- Пригодность для голосовой связи не наследуется из успешной загрузки HTML.
- Длительный payload-тест не запускается при каждом наведении или движении карты.

Для небольшой выборки показывать число успешных проверок из числа завершённых. Не писать «0% потерь» в виде уверенного свойства по нескольким ответам. Точная статистическая модель будущего рейтинга версионируется; краткие UI-состояния остаются понятными.

## 7. Правила отображения и производительности

Из текущего каталога известны верхние границы 10 000 Windows-кандидатов и 2 000 Android-кандидатов. Геометрия рисуется слоями с кластеризацией, без отдельного DOM/View на каждый узел. Список остаётся постраничным. Карта не должна снова ограничить доступные записи историческим preview на 200 элементов. [Пул](../../PUBLIC-POOL-2026-11-18.md), [актуальный выбор](../../SERVER-SELECTION-2026-11-18.md).

Предлагаемые правила первой версии:

| Ситуация | Поведение |
|---|---|
| Много узлов в городе/стране | Кластер с числом; раскрытие с сохранением выбранного приложения |
| Тысячи кандидатов | Рисовать слой кластеров; детали только выбранного узла |
| Активный фильтр/поиск | Одно состояние между списком и картой; unknown geography не теряется |
| Фоновая новая проверка | Обновить состояние узла; не пересортировать уже изучаемый список и не двигать камеру |
| Изменение размера/поворот | Сохранить выбранный узел, фильтр, контекст и незавершённый draft |
| Смена вкладки/фон Android | Приостановить анимацию и лишние перерисовки; не держать активные проверки ради скрытой карты |
| Нет GPU/WebGL или ошибка карты | Рабочий список, короткое объяснение и повтор открытия; VPN продолжает работу |
| Потерян интернет | Локальная карта и сохранённые кандидаты доступны; старые результаты явно устарели |
| Нет выбранной цели | Показать устройство → узел; не рисовать выдуманный сервер игры |

Линии по умолчанию рисуются для текущего и выбранного сравниваемого пути, а не для всех 10 000 узлов. Предварительный предел визуального сравнения — три альтернативы; это UX-ограничение, не лимит каталога. Никакого постоянного свечения, вращения глобуса или движения пакетов ради оформления. Reduced motion соблюдается.

Обновления метрик объединять; начальный проектный максимум пересборки слоя — два раза в секунду при видимой карте, с немедленной реакцией на локальный выбор. Это целевой бюджет для измерения, не результат benchmark. Окончательное значение закрепляется по WN-03.

## 8. Community Atlas: что требуется подготовить уже сейчас

В первой версии локальная схема должна хранить метод, время, контекст и provenance так, чтобы впоследствии можно было добавить коллективные данные. Сам серверный контур сейчас не разрабатывается.

Пользователь отдельно включает отправку агрегированных результатов. Отказ не ухудшает локальный каталог, выбор и диагностику. Включение общей аналитики приложения, если она появится, не равно согласию делиться сетевыми измерениями.

Первая допустимая область Community — **уже опубликованные в общем каталоге узлы** и заранее определённые контрольные цели. Личные узлы, частные подписки, произвольные посещаемые домены, списки процессов, Wi-Fi SSID/BSSID, локальные network fingerprints и IP устройства в payload не включаются.

| Предлагаемое поле отчёта | Зачем | Ограничение |
|---|---|---|
| ID публичного узла из registry | Сопоставить результаты | Не хеш конфигурации с личными ключами; ID публикует registry |
| Страна/крупный регион источника | Различать доступность | Из явного разрешённого источника, не точная координата |
| ASN | Пригодность по операторской сети | Только если отдельная оценка риска и малых выборок допускает; по умолчанию может отсутствовать |
| Версия метода/клиента | Воспроизводимость | Без уникального device ID |
| Окно времени | Свежесть | Округление, а не точная история действий |
| Метод и счётчики | Успех, timeouts, размер выборки | Чужие таймауты и отмена не становятся сетевыми отказами |
| Квантили latency | Сводное качество | Только для сопоставимых методов и достаточной выборки |

Такой payload ещё нельзя называть анонимным: сервер принимает сетевое соединение и видит IP отправителя, а редкое сочетание региона, времени и ASN может быть узнаваемым. До включения нужны конкретные правила логирования, хранения, удаления и укрупнения данных. Не обещать анонимность из отсутствия поля IP.

## 9. Качество коллективных данных

Один злоумышленник может отправить много отчётов; подпись клиента не доказывает истинность измерения. Несколько зеркал одного списка не означают разных операторов. Поэтому:

1. Ограничить частоту, объём и повтор одной группы измерений.
2. Хранить версию метода и исключать несопоставимые показатели.
3. Учитывать независимость наблюдений как неполное свидетельство; не обещать решение Sybil-проблемы одной подписью.
4. Применять затухание по времени и гистерезис к репутации.
5. Не публиковать малые/редкие срезы; минимальный порог и окно задать по пилоту до запуска.
6. При аномалии переводить рейтинг в «недостаточно данных», а не в фиктивный ноль или сто.
7. Локальная проверка выбранного узла имеет приоритет над общей статистикой. Community подсказывает порядок кандидатов, но не разрешает маршрут.
8. Коллективный рейтинг никогда не включает public в личный Auto и не снимает TLS-проверку.

Нужна административная возможность исключить испорченный dataset и откатиться на предыдущий. Подписанный registry защищает происхождение обновления, но не доказывает порядочность сервера. Протокол подписи, доверенные ключи и ротация — решение отдельного Community-этапа; самодельную PKI сейчас не вводить.

## 10. Контур контрибуции

Полезные вклады: исправление metadata/provenance, уточнение публичного источника, профиль приложения, воспроизводимый сценарий проверки и перевод коротких UX-текстов.

Для профилей использовать существующий Git review и декларативные данные. Связанные с игровым сервером IP/домены могут меняться; требуется срок проверки, источник, версия и допустимые тесты. Не принимать исполняемые скрипты, бинарники и чужие credentials. Профиль приложения не выбирает провайдера и не переводит трафик на публичный узел без выбора пользователя.

До публикации Community полезны три артефакта: описание формата данных, несколько проверенных примеров без секретов и чеклист воспроизводимости. Автоматические боты публикации и PR не относятся к данной подготовке.

## 11. Приёмка Atlas

- Карта и список имеют один набор ID, поиск, фильтры и выбор; переключение представления не меняет маршрут.
- В offline есть карта-основа, список и понятные состояния; недоступный внешний ресурс не блокирует управление сетью.
- Для 10 000/2 000 кандидатов интерфейс не создаёт тысячи карточек одновременно и не гоняет весь snapshot на каждом тике.
- Показанные координаты имеют provenance; метки страны не выглядят точными точками.
- Точка «Вы» не определяется как VPN exit. При неизвестном регионе нет ложной позиции.
- Переход на другую сеть и смена effective endpoint инвалидируют зависимые измерения.
- Нет фоновых внешних запросов геолокации или новых сетевых проверок от hover/pan/zoom.
- Подробности не перекрывают Android primary action/IME/system bars; список всегда доступен без жеста по карте.
- Состояние выбранного пути отражает подтверждённый runtime; сохранение старых сессий допускает одновременно новый путь для новых соединений и старый draining-путь.
- Все новые значения явно различают measured/derived/claimed/unknown. Финальная визуальная и нативная проверка привязана к одному исходному commit.

Порядок выполнения и метрики — [05-PLAN-AND-ACCEPTANCE.md](05-PLAN-AND-ACCEPTANCE.md). Никаких измерений новой функции в рамках подготовки не проводилось.

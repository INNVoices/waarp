## Что вошло в приложение

### Карта в существующем выборе

Windows Connections и ServerPicker получили переключатель списка и карты; Android — такой же дополнительный вид в «Туннелях» и подшаге существующей формы маршрута. Поиск, фильтр страны, страницы и явное действие выбора продолжают использовать существующий каталог. Агрегация карты учитывает отфильтрованный пул целиком. Регион без координат остаётся доступным через список и unknown-фильтр.

Открытие карты, смена региона и панорамирование не запускают apply, VPN или новые проверки. Маркеры означают регион из источника, не местоположение серверной стойки. Регион пользователя задаётся вручную; внешний адрес VPN не выдаётся за домашнее местоположение. Линия Windows показывает логическую связь с подтверждённым текущим путём, не traceroute. Android отдельно называет путь, выбранный в форме; этот черновик не объявляется активным native выходом.

Карта и география локальные: MapLibre и Natural Earth, без внешнего tile/GeoIP сервиса. При отказе WebGL остаётся рабочий список. Скрытая Windows-карта освобождает renderer/worker. Новые Android location/Wi-Fi permissions, приходящие из SDK, исключаются из manifest; APK verifier проверяет отсутствие этих разрешений. Upstream pins, данные и полные включённые notices описаны в [ATLAS-DATA.md](../../ATLAS-DATA.md).

### Проверка из карточки и объяснение результата

Карточка передаёт свою цель, путь и назначение в существующую диагностику. Preset предлагает документированный домен; имя EXE или package name не превращается в предполагаемый адрес. Проверка остаётся явной, ограниченной и отменяемой: Windows до четырёх путей по два HTTP(S)-запроса, Android до трёх путей по два HTTPS-запроса. Android при ON использует допустимые уже загруженные пути.

Отвечающий текущий путь сохраняется. Для автоматической рекомендации нужны два завершённых отказа текущего и два ответа альтернативы. Отмена, отсутствие измерения и неподдержанный метод не превращаются в отказ. Windows сохраняет доверенный порядок допустимых альтернатив; Android выбирает минимальную медиану HTTPS только среди альтернатив с двумя ответами после двух отказов текущего. Это ограниченный алгоритм восстановления доступности адреса.

В Windows применение изменяет конкретную карточку через прежнего владельца apply. В Android результат меняет только draft и перепроверяется перед единственным «Сохранить маршрут». Proof связан с целью, карточкой, назначением, профилями, сетью, revision и native context; действует не более пяти минут и не переживает несовместимую смену контекста. Одинаковые выполняющиеся запросы в подтверждённо одинаковом контексте используют одно измерение. Windows не объединяет запросы при неизвестной сети. Новый явный Check после завершения получает свежие измерения.

Системные DNS/TCP/TLS/HTTP этапы Windows обозначены своим действительным scope: при работающем VPN они могут следовать маршрутам ОС. Они не доказывают обход через native Direct. Измерение конкретного подключения адресуется его native outbound.

### Меньше ненужных переключений

Windows использует того же сериализованного владельца native изменений. Необязательное улучшение и возврат с работающего резерва удерживают путь при активных соединениях, соседних каналах того же физического пути или неизвестном состоянии трафика. Известный idle требует свежих наблюдений и пяти секунд непрерывного отсутствия потоков; повреждённая или устаревшая телеметрия не доказывает idle.

Ручное намерение имеет приоритет над следующими автоматическими PUT. Уже отправленный PUT доводится до ACK и учитывается; поздний ACK не превращается в потерянное неизвестное состояние. OFF инвалидирует незавершённый переход. Подтверждённый отказ и запрет старого пути продолжают иметь приоритет над сохранением потока.

Production selectors сохраняют `interrupt_exist_connections: true`. Включённый результат — консервативное удержание рабочего пути. Отдельный Windows experiment доказал поддержку soft/strict на закреплённом core в loopback; произвольный ручной drain и перенос сессии между внешними IP этим результатом не установлены.

### Чего численные результаты не доказывают

Controller PUT+GET ACK 6.85/6.63 ms из предыдущего `6df55eba` [loopback report](evidence/windows-selector-continuity-final.json) относится к одному Windows experiment с локальными SOCKS endpoints. Он не равен времени паузы игры, обнаружения отказа, TLS handshake или повторной авторизации. Soft сохранил старые TCP/UDP через A и направил новые через B; strict закрыл старые TCP и SOCKS UDP association, после чего новые соединения использовали B.

Цели исходного плана p95 UI ≤100 ms, p95 frame ≤33 ms, flow gap ≤baseline+50 ms и ready-reserve recovery ≤1 s не подтверждены этими прогонами. Projection fixtures для большого каталога не являются замером FPS реального устройства. Полная матрица fontScale 1.0/1.3/2.0, TalkBack, landscape и physical network handover для новых компонентов не объявляется пройденной.

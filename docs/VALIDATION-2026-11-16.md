## Windows

[PR #14](https://github.com/INNVoices/waarp/pull/14) запускает обязательный `checks (windows)`. Job выполняет весь набор, production DOM-проверки в Chromium и сборку portable EXE с проверенным закреплённым ядром. Результат конкретного head и артефакты доступны во вкладке Checks; слияние допускается только после успеха обязательного job.

В первом Windows-прогоне реально выполнены **18 native process checks** и **51 relaunch check**, включая ожидание настоящего дочернего процесса. Этот job в целом первоначально отказал на старой фикстуре `core.check`: она ожидала блокировку повреждённого журнала даже после доказанного отсутствия соответствующего процесса. Фикстура исправлена так, чтобы использовать имя действительно работающего Node-процесса; теперь она проверяет отказ при наличии чужого живого процесса и сохранение свидетельства. Путь восстановления для отсутствующего процесса проверяется отдельно в journal-наборе. Повторный focused Linux-прогон этой фикстуры: 131 non-IPC проверка.

Повторный Windows-прогон на commit `f4e303e5320065ff7a79d7c2145c19403064fd68` завершился **SUCCESS**: [run 43891541976](https://github.com/INNVoices/waarp/actions/runs/43891541976). Выполнены все 34 набора, 18 native process checks, 51 relaunch check и 16 Chromium-регрессий; portable EXE собран. Это доказательство для предыдущего среза. Финальные исправления no-console, UI истории, зависимостей и новые stability gates требуют нового успешного CI на актуальном head.

CI сохраняет `waarp-ui-evidence` со снимками и UI-метриками, `waarp-validation-evidence` с native/performance JSON, `waarp-awg-evidence` с протокольным стендом и `waarp-windows-portable` с EXE. Native process tests не создают TUN. Отдельный 50-cycle runner создаёт настоящий временный TUN без автоматической маршрутизации и захвата DNS. Он не подключается к приватному серверу и не доказывает полную маршрутизацию.

## Как повторить полноценную проверку

На Linux с доступным UDP до сервера и разрешённым обычным netlink:

```bash
node scripts/test-connection.mjs \
  --engine /path/to/pinned/sing-box \
  --config /private/client.conf \
  --report /private/connection-results.json
```

Этот явно запускаемый сценарий проверяет реальный API, HTTP через AWG, селекторы, штатный OFF, SIGKILL своего процесса, удаление профиля без перехода на Direct, повторный импорт и запуск. Обычный `npm test` его не запускает. Отказ удалённого запроса не трактуется как успешная проверка туннеля.

Тест в userspace не подтверждает системную маршрутизацию Windows, поведение Wintun, сон физического компьютера или поведение других VPN. Эти границы сохраняются даже при зелёном CI и успешном локальном протокольном стенде.

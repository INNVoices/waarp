# Локальный мост для приложений-компаньонов

Другое приложение на этом же компьютере может попросить Waarp вести трафик к своему адресу: напрямую, через Авто или через конкретное подключение, которое пользователь выбрал в Waarp. Приложение не видит ключи, адреса серверов и конфиг движка, а включить или выключить туннель через мост нельзя.

## Канал

- Windows named pipe `\\.\pipe\waarp`, поднимается при старте Waarp.
- Протокол: одна строка JSON на запрос, одна строка JSON на ответ (`\n` в конце). Не больше 64 КБ на строку и 100 запросов на соединение.
- Токен доступа: `%APPDATA%\Waarp\bridge.json` (`{ pipe, token, api, pid }`), новый при каждом запуске. Файл закрыт ACL: другие обычные пользователи Windows его не прочитают. Кто прочитал токен, тот и компаньон.
- `id` запроса: число, строка до 128 символов, `null` или нет поля. Другое даёт `bad_request`. Ответ возвращает тот же `id`.

```json
→ { "id": 1, "token": "<token>", "method": "hello" }
← { "id": 1, "result": { "app": "waarp", "version": "0.4.0", "api": 1, "methods": ["hello", "status", "log", "routes.list", "routes.ensure", "routes.open"], "planned": [...] } }
```

Ошибки: `unauthorized`, `bad_json`, `bad_request`, `unknown_method`, `not_implemented`, `internal`.

## Методы

| метод | что делает |
|---|---|
| `hello` | версия, номер API, список методов |
| `status` | `{ phase, mood, version, since? }`: фаза движка, `mood` (`ok` / `recovering` / `attention`), версия Waarp, время начала фазы. Без серверов, адресов, id, пингов и текста движка |
| `log` | последние 300 строк журнала движка; ключи и токены маскируются до ответа |
| `routes.list` | маршруты компаньонов: `{ id, name, intent, on, state, reason?, via? }`, где `via` только отображаемое имя |
| `routes.ensure` | `{ target, intent }`: сохранить намерение для цели. Туннель при этом не включается |
| `routes.open` | `{ target }`: показать маршрут в Waarp или открыть выбор подключения. Ничего не меняет |

`connect`, `disconnect`, `routes.remove` и `probe` зарезервированы и отвечают `not_implemented`.

### Цель

```json
{ "id": "ext:demo:app", "name": "Demo App", "host": "companion.example.com" }
```

- `id` вида `ext:<namespace>:<target>`, только `a-z0-9-`;
- `name` до 40 символов, без управляющих;
- `host` один нормализованный домен: без схемы, пути, порта, логина, маски и IP;
- других полей нет. Цель с уже занятым `id` нельзя переопределить: другой `host` или `name` дают `conflict`.

### Намерения

| intent | что значит |
|---|---|
| `direct` | напрямую |
| `auto` | Авто: только свои подключения, никогда не напрямую и не через публичные узлы. Если своих нет, `no_auto` |
| `waarp` | конкретное подключение, выбранное в Waarp. Если его ещё нет, `needs_choice`, и приложение вызывает `routes.open` |

Ошибки `routes.ensure`: `bad_target`, `bad_intent`, `conflict`, `no_auto`, `needs_choice`, `blocked`, `not_saved`.

Успешный ответ разделяет сохранение и применение: `{ ok: true, saved: true, applied, warning?, route }`.
- `applied: true`: работающий туннель уже использует маршрут;
- `applied: false` без `warning`: Waarp закрыт, намерение сохранено и сработает при следующем включении;
- `warning: "blocked"`: запуск сейчас заблокирован (например, другой VPN), туннель остановлен, намерение сохранено;
- `warning: "not_applied"`: намерение сохранено, но текущее состояние туннеля не применило изменение.

`not_saved`: запись не удалась, прежние настройки остались.

## Правила безопасности

- маршрут компаньона это обычная карточка Waarp с меткой источника; пользователь видит её, меняет путь, выключает и удаляет
- путь такого маршрута: Напрямую, Авто, своё подключение или группа, где каждый участник своё живое подключение. Никогда публичный узел, отозванное или удалённое подключение, и запасной путь тоже только свой
- если выбранный путь стал небезопасным, `routes.ensure` отвечает `blocked` и ничего не подменяет
- новое намерение сбрасывает запасной путь
- изменения маршрутов через мост идут по одному, в порядке запросов
- закрытый Waarp остаётся закрытым: мост только сохраняет выбор
- интерфейс Waarp не может создать маршрут компаньона или поменять его цель

## Граница доверия

Мост защищает от других пользователей Windows, а не от программ, уже запущенных под вашим пользователем.

- ACL файла с токеном закрывает его от других обычных пользователей этого компьютера;
- процесс, работающий под тем же пользователем Windows, скорее всего сможет прочитать токен и данные Waarp;
- у кого токен, тот может вызывать методы моста;
- это не песочница и не защита от вредоносной программы под вашим пользователем. Методы моста поэтому ограничены: без ключей, конфигов, адресов серверов и без включения туннеля.

# Служебные зависимости Waarp

Опись внешних адресов, к которым обращается само приложение (не трафик пользователя), и поведение при их недоступности. Срез: ноябрь 2026, Э7 из `TZ-NEXT-2026-11.md`.

| Зависимость | Где в коде | Когда обращается | Если недоступна |
|---|---|---|---|
| Источники публичного каталога (GitHub raw ×5, vpngate.net) | `catalog.ts` `SOURCES` | Только по явному «Обновить» в разделе публичных узлов | Ошибка показывается по каждому источнику; если ни один не скачался или ни один узел не ответил — остаётся прошлый рабочий список с прежним временем проверки. Запуск не ждёт каталог |
| Источники доменных списков (добавляет пользователь) | `lists.ts` | При добавлении, по «Обновить», фоново раз в 24 ч для включённых | Последняя рабочая версия сохраняется; ошибка и время последнего обновления видны в настройках; повторов нет до следующего суточного окна или ручного «Обновить» |
| Подписки пользователя | `vless.ts` `fetchSubscription`, `subscription.ts` | По «Обновить подписку» | Профили остаются как были; пропавшие помечаются, но не удаляются |
| Цели проверки задержки: `www.gstatic.com/generate_204`, `cp.cloudflare.com/generate_204` | `engine.ts` `delay` / `probe2`, `checker.ts` | Раунды здоровья туннелей (15 с) и проверки | Две независимые цели: отказ одной не помечает туннель сломанным; отказ обеих = «туннель не ответил», маршрутизация не меняется сама |
| DoH `1.1.1.1` / `1.0.0.1` (`cloudflare-dns.com`) | `layered.ts` | Только в «Почему не открывается?» | Слой DoH показывается как недоступный; это не становится выводом о блокировке |
| DNS через HTTPS в конфиге ядра (`1.1.1.1`) для подключений без своего DNS | `awg.ts` резолверы | Пока работает туннель | Это DNS внутри туннеля; при его отказе страдают только домены этой карточки |
| Обновления приложения | — | Нет автообновления | — |

## Правила

- Запуск приложения и уже сохранённые карточки и подключения не зависят ни от одного внешнего адреса.
- Рабочий файл (каталог, список, подписка) заменяется только проверенным результатом.
- Публичные узлы никогда не подставляются молча ни для пользовательского трафика, ни для служебных загрузок.
- Служебные загрузки идут напрямую из процесса Waarp (правило `selfExe → direct`).

## Не сделано

- **Служебные загрузки через разрешённый личный путь — не реализованы.** Кэш и ограниченные обновления приняты отдельно; весь Э7 поэтому не отмечается DONE. Текущая реализация использует Direct. Личный путь требует явного выбора и проверенного клиента к закрытому локальному входу ядра; просто открыть прокси без аутентификации недостаточно. Отсутствие готового клиента в зависимостях — незавершённый подпункт реализации, а не доказанная невозможность движка или ограничение сети. Это расширение не включено в первый обязательный проход Э0 → Э1 → Э5.
- Подписанные зеркала, аварийный набор и автообновление — следующие отдельные задачи (§6.4).

# Сборка и открытый upstream advisory — 18.11.2026

Функциональные проверки текущего `main` и строгий аудит npm выполняются отдельными заданиями CI. Ошибка аудита не скрывает результаты typecheck, регрессий, реального TUN-теста, упаковки и проверки APK. Сам аудит не ослаблен и не помечен успешным при обнаруженных уязвимостях.

На этом срезе `npm audit` сообщает **GHSA-fc5q-39xc-vjpf / CVE-2026-112366** в `picomatch <= 4.0.7`. Патч-релиз в npm ещё не опубликован (`npm view picomatch version` возвращает `4.0.7`). Рекурсивные записи о Vite, Electron Builder и остальных build-зависимостях происходят из того же транзитивного узла; автоматически предлагаемый downgrade всей сборочной цепочки не является подтверждённым исправлением.

Источники: [GitHub Advisory Database](https://github.com/advisories/GHSA-fc5q-39xc-vjpf), [upstream issue](https://github.com/micromatch/picomatch/issues/242), [upstream PR 194](https://github.com/micromatch/picomatch/pull/194), [история релизов picomatch](https://github.com/micromatch/picomatch/releases).

`npm audit --omit=dev --audit-level=moderate` проходит на текущем lockfile: этот пакет относится к сборочным зависимостям. Это **не закрывает advisory** и не заменяет полный аудит. Полный security job остаётся красным, пока не появится проверенное исправление. Непроверенный патч, скрытый allowlist и отключение аудита не добавлены.

Повторный [аудит коммита `f66e5def3d68`](https://github.com/INNVoices/waarp/actions/runs/44276975073/job/134707494740) подтвердил ноль найденных уязвимостей в production-зависимостях и отказ полного аудита с 10 high-записями, связанными с этим узлом сборочной цепочки. Успешный preview workflow не означает, что отдельный security job прошёл.

Android native source build использует кэш только при точном совпадении source/patch/pin/verification inputs. Перед установкой AAR проверяются `sourceInputsSha256`, успешный отчёт исходной сборки, размер и SHA-256 из production pin. Изменения Kotlin/UI не требуют повторно собирать неизменившиеся три native ABI.

При первом переходе на ключ v2 допускается восстановить прежний **точный** source-cache v1, без поиска по широкому prefix. Он проходит те же обязательные проверки текущих source inputs и замороженного AAR до использования и сохранения как v2. Прежний успешный build-report содержит `fb320151…` / `1edc7454…`, совпадающие с текущим production pin; это не разрешение принять другой бинарник или пропустить новую проверку.

Освобождение места выполняется только на одноразовом `github-hosted` builder и затрагивает указанные неиспользуемые предустановленные инструменты. `TMPDIR` выделен внутри `RUNNER_TEMP`. Пользовательские машины и артефакты репозитория не очищаются.

Тесты и упаковка заканчиваются до выгрузки артефактов. В Android build job до первого upload дополнительно запускается эмулятор API 35 с фактически собранными APK: два теста проверяют восемь изменений маршрутов с подтверждениями ядра в одном реальном TUN и владение сессией главной кнопкой, ещё три — положение элементов и доступность обратной связи UI. Принимаются только все пять названных тестов без пропусков и полный JSON непрерывности маршрутов. Это не тест доступности внешнего VPN-сервера. Полная матрица API 29/35/36 и release journeys сохранена отдельно.

Отчёты JVM/APK/native и результат этой проверки печатаются в журнале перед upload, чтобы превышение GitHub artifact quota не стирало доказательства сборки и не мешало запустить основной регрессионный TUN-тест. Ошибка upload остаётся ошибкой доставки; она не выдаётся за успешную публикацию APK или portable-файла. Старые временные `network-pass`/`review-*` workflows удалены: они проверяли закреплённые промежуточные коммиты вместо текущего приложения.

На итоговом исходном коде preview r5 [`928c9a8`](https://github.com/INNVoices/waarp/commit/928c9a8e3cd0a83a41ebfa15c2628ddb610ea157) [security job 134844018010](https://github.com/INNVoices/waarp/actions/runs/44316534397/job/134844018010) снова подтвердил `found 0 vulnerabilities` для runtime и 10 high-записей полного audit по тому же advisory. [Preview run 44316534164](https://github.com/INNVoices/waarp/actions/runs/44316534164) успешно опубликовал EXE/APK напрямую в Releases после функциональных gates; это не исправление advisory и не успешный общий security job.

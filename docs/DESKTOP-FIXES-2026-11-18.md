# Исправление ПК-версии после проверки пользователем — 18 ноября 2026

Опубликован [preview r6](https://github.com/INNVoices/waarp/releases/tag/preview-2026-11-18-r6): **Windows 0.4.1-rc.5**, исходный коммит [`0e0bb6c7cad421dc0fff377d8c7f826d115e0292`](https://github.com/INNVoices/waarp/commit/0e0bb6c7cad421dc0fff377d8c7f826d115e0292). Область: публичные подключения, диагностика, карта и иконка Windows. Android в этом выпуске не менялся. Причина этой доработки — реальные кадры пользователя: 6164 кандидата при нуле доступных, ручная проверка через добавление, пустая карта сохранённых DE/MY-серверов, узкая карта, малоинформативная диагностика и стандартная иконка окна.

## Исправления

| Проблема | Подтверждённый дефект | Изменённое поведение |
| --- | --- | --- |
| Каталог не находит доступные узлы | Один обход завершался после 64 кандидатов; видимые строки не обязаны были попадать в выборку | Автоматический ограниченный обход продолжается, пока открыт экран; видимые узлы получают приоритет, проверка не импортирует их |
| Часть поддерживаемых узлов не проверяется | Подготовка пропускала доменные gRPC/XHTTP и неявные HTTP Host; мог выбираться первый AAAA вопреки IPv4-политике checker | Сохраняются исходные TLS/HTTP-параметры закреплённого движка; при наличии проверенного A-ответа используется IPv4 |
| Неясно, сервер недоступен или сломан проверяющий процесс | Неудачи подготовки и запуска терялись; один невалидный outbound мог сорвать всю партию | Отдельные состояния DNS/конфигурации/движка/ответа; невалидная конфигурация изолируется; непроверенные узлы не объявляются недоступными |
| Для проверки предлагается добавить сервер | Основное действие объединяло проверку и импорт | Проверка идёт заранее; «Добавить» или «Использовать» доступно после свежего ответа |
| Пустая карта при нуле ответов | Фильтр доступных скрывал весь пул | По умолчанию видны кандидаты и состояния проверки; явный пустой фильтр позволяет вернуться ко всем |
| Сохранённые Germany/Malaysia без региона | География не переносилась для части типов профилей и не восстанавливалась по явному названию | При импорте сохраняется страна; старые DE/MY-названия восстанавливаются без выдуманного положения произвольных узлов |
| Карта — узкая полоса | Высота ограничена 340 px | Основная карта до 56% высоты окна, максимум 720 px; региональные количества, свежие HTTP-ответы, цвет состояния, подписи и сведения при наведении |
| Диагностика не помогает | Проверка только по кнопке, измерения без понятного следующего шага, основные блоки заняты графиком и передачей файла | Автоматическое расследование адреса, конкретный этап и следующий шаг, существующий маршрут, отдельный разбор системного запроса; дополнительные измерения раскрываются по запросу |
| Ошибка первого IP выглядит как отказ сайта | TCP/TLS проверяли только первый DNS-адрес | До четырёх адресов обеих IP-семейств в общем бюджете этапа; проигравшие запросы отменяются |
| Работающему пути может предлагаться замена | Общий разбор не всегда учитывал текущий/default/public outbound | Измеренный работающий путь сохраняется; рекомендация требует подтверждённых неудач текущего и ответов альтернативы |
| Стандартная иконка в панели задач | `BrowserWindow` ссылалось на `build/icon.png`, отсутствующий в пакете | Файл включён в приложение; упаковка сравнивает его байты с исходным, запуск EXE проверяет чтение иконки |

## Границы измерений

Показанное время — ответ HTTP(S), а не пинг игры, скорость доступа, географическая удалённость или доказательство UDP-качества. Отказ одного публичного узла не означает отказ всего каталога. Положительный ответ относится к конкретному узлу, времени и сети проверки.

Страна на карте происходит из метаданных/названия источника; точка пользователя задаётся вручную. Карта не выполняет скрытый GeoIP-поиск и не изображает реальный трассировочный маршрут. Без сведений о стране узел остаётся в списке.

Диагностика не меняет маршрут автоматически. Системные DNS/TCP/TLS/HTTP-запросы Windows и измерение явно выбранного outbound показаны отдельно: отказ системного пути не опровергает ответ работающего туннеля.

В логе сохранена отдельная ошибка native lifecycle; её причина и окончательное состояние очистки не установлены. Расхождение с успешными 50 циклами preview остаётся открытым. [Точная сводка general CI](screenshots/preview-r6/general-ci-windows.json) · [фрагмент native failure](screenshots/preview-r6/native-failure-excerpt.log).

В том же general CI функциональные AWG/Linux-проверки прошли, сохранение их артефакта упёрлось в квоту. Audit поставляемых JavaScript-зависимостей: **0 vulnerabilities**; полный audit инструментов сборки: **10 high**, цепочка `picomatch`, [GHSA-fc5q-39xc-vjpf](https://github.com/advisories/GHSA-fc5q-39xc-vjpf). Общий CI не объявляется полностью зелёным.

Проверка публичных узлов выполнена в сети GitHub-hosted Windows runner. Она подтверждает прохождение реального сценария в этой сети и в это время; доступность этих же сторонних узлов у конкретного провайдера пользователя отдельно не измерена. Показанные задержки — HTTP(S)-измерения, а не обещание игровой задержки или бесшовного переноса любых соединений.

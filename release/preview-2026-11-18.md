# Waarp preview r4 — 18 November 2026

**Windows 0.4.1-rc.4 · Android 0.5.0-rc.5**

A completed preview of the local map, contextual connection checks and conservative route continuity. This release is kept as a draft until both platform jobs and the final file-integrity gate succeed.

## Map and selection

- **Windows:** List/Map inside the existing connection browser and per-app server picker. Search, country filters, paging and the explicit server-selection action stay together.
- **Android:** Map inside Tunnels and the current route form. A selected path stays in the draft until the single **Save route** action.
- The manually chosen Android region is one local UI preference shared by the map and route forms; switching List/Map preserves it.
- Geography is bundled locally with MapLibre and Natural Earth. Country markers are regional groups; the user's region is manual. Unknown regions stay selectable in the list.
- Browsing the map does not start VPN or apply a route. A graphics failure retains the list.

## Contextual checks and continuity

- A card opens the existing diagnostics with its own target, path and purpose. Checks are bounded and cancellable; identical in-flight requests share one measurement.
- A responding current path is kept. An automatic alternative requires two completed failures of the current path and two responses from the alternative. A stale result cannot be applied after an incompatible context change.
- Windows applies to the exact card; Android changes only the draft and revalidates before Save.
- Windows holds optional changes during active or unknown flow state. Explicit user actions take priority; OFF and confirmed failures retain their existing authority.
- Measurements describe HTTP(S) availability. Game/voice UDP quality, loss, jitter and physical-network session migration are not established by these checks.

## UI completion

The existing navigation and forms contain the new controls. Android map actions have reserved space above the import button. Enlarged text and long region names are part of the actual UI checks. Windows map selection and route state update with the visible data instead of waiting behind a general debounce.

## Acceptance boundary

The preview requires the existing Windows functional, renderer, native-routing, TUN-lifecycle and package gates and Android build, APK integrity, focused native route and real UI gallery gates on this exact commit. The final gate verifies uploaded digests and the complete installable asset set. Delivery uses the existing direct GitHub Releases path; ordinary Actions artifact storage is not required.

This remains a prerelease. Full physical-device, optimized-production and two-hour acceptance are separate [stable criteria](../docs/RELEASES.md). The independent unpatched build-tool advisory remains disclosed in [the build audit](../docs/BUILD-AUDIT-2026-11-18.md); it is not presented as a passing audit. Public server availability still depends on the endpoint and network.

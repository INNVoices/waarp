# Waarp preview — 18 November 2026

**Windows 0.4.1-rc.3 · Android 0.5.0-rc.4**

This is a prerelease for testing. The workflow keeps it as a draft until both platform jobs and the final file-integrity gate succeed.

## Windows: choose a server and keep Waarp running

- **One server picker after choosing an app.** Automatic, manual and Direct modes share one screen. Saved connections and public servers are visible tabs; individual servers appear as compact rows.
- **Search the whole public pool.** Region and availability filters, numbered pages and previous/next controls replace the old 200-candidate sample and “show more” list. Saved connections have pages too.
- **Availability is measured.** The catalogue leads with servers that have a fresh successful check. With no fresh results, opening the public section starts one bounded search. Choosing a candidate checks its actual connection before adding it.
- **Checks work while the VPN is on.** Public-node verification uses an isolated local checker without creating another TUN or replacing the active one.
- **Change a card's server without a VPN-restart dialog.** Live route updates preserve the owned VPN session. A failed application keeps the previous selection and returns an error. Connections affected by a successful path change may need to reconnect; unrelated routes retain their session.

The initial application chooser remains unchanged. Route diagrams, fallback and advanced options are available under **Parameters and connections**. [Detailed behavior](../docs/SERVER-SELECTION-2026-11-18.md).

## Android

The Android version remains **0.5.0-rc.4**: native Kotlin/Compose UI, Android VpnService, selected-app routing, supported protocol imports, public-pool refresh and diagnostics. The Windows picker changes above do not describe the Android UI.

The APK targets below are **debug-signed development builds**, package ID `local.waarp.android.debug`. They install alongside the production app and cannot update a production-signed installation.

## Validation scope

The preview runs Windows functional, renderer, native-routing, TUN-lifecycle and packaging gates, plus the Android build, integrity and focused API 35 route tests. Stable approval still requires the full [Windows matrix](../docs/STABLE-AUDIT-2026-11-16.md) and [Android optimized-release and two-hour soak acceptance](../docs/ANDROID.md#optimized-release-approval).

Public server availability depends on the endpoint and your network. Waarp does not promise multipath aggregation, lower game latency or an independent firewall kill switch. The separate build-tool security advisory is recorded in [the build audit](../docs/BUILD-AUDIT-2026-11-18.md).
